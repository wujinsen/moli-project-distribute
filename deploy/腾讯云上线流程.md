# Moli 生产上线流程（腾讯云 · Ubuntu）

> **适用**：腾讯云 CVM · **Ubuntu 22.04 / 24.04 LTS**（验证环境：Ubuntu 24.04 Noble）  
> **不适用**：AWS EC2 · Amazon Linux —— 见 [`上线流程.md`](上线流程.md)（AWS 专版）  
> **工程 Runbook 索引**：[`docs/ops/tencent-cloud-release-runbook.md`](../docs/ops/tencent-cloud-release-runbook.md)  
> **敏感文件**：`application-pro.yml` / `conf/moli-*.env` **不提交 Git**；模板见 `deploy/linux/moli-*.env.example`

**部署根目录**：`/opt/moli-project-distribute`（与 AWS 版一致，便于迁移）  
**CVM 默认登录用户**：`ubuntu`（腾讯云 Ubuntu 镜像自带，本文后续命令均在此用户下执行）  
**本批服务**：user-center · knowledge · gateway（v1 最小三件套）

## 0. 与 AWS 版差异速查

| 项 | AWS（[`上线流程.md`](上线流程.md)） | 腾讯云（本文） |
|----|-------------------------------------|----------------|
| 计算 | EC2 | **CVM** |
| 防火墙 | Security Group | **安全组** + 可选 **UFW** |
| 系统镜像 | Amazon Linux 2 / 2023 | **Ubuntu 22.04 / 24.04** |
| 包管理 | `yum` / `dnf` | **`apt`** |
| JDK 11 | Amazon Corretto（`java-11-amazon-corretto`） | **OpenJDK 11** 或 **Temurin 11** |
| `JAVA_HOME` 示例 | `/usr/lib/jvm/java-11-amazon-corretto` | `/usr/lib/jvm/java-11-openjdk-amd64` |
| Python pip | `yum install python3-pip` | `apt install python3-pip` |
| 代码上传 | EC2 `git pull` / scp | CVM `git pull` / **SCP / SFTP / 云助手**（用户 **`ubuntu`**） |
| 系统登录用户 | `ec2-user` / `ubuntu`（视 AMI） | **`ubuntu`**（腾讯云 Ubuntu 镜像默认） |
| 对象存储（可选） | S3 | **COS**（插图包、备份；非 v1 必需） |

> **勿混淆**：**`ubuntu`** = 服务器 OS 用户 · **`root`** = 唯一 MySQL 账号 · **`moli`** = 库名（见 §3.2 表）

**业务逻辑、目录布局、启停脚本、DB/Sync/冒烟** 与 AWS 版相同；仅 **OS 安装命令、防火墙、JDK 路径** 按本文执行。

## 1. 腾讯云资源规划

### 1.1 推荐规格（单机 v1 最小）

| 资源 | 建议 | 说明 |
|------|------|------|
| CVM | 4 vCPU · 8 GiB 起 | user-center + knowledge + gateway + MySQL + Redis + Nacos |
| 系统盘 | 50 GiB SSD 起 | 含 `kb/`、日志、MySQL 数据 |
| 公网 IP | 弹性公网 IP | 仅 **80/443** 对公网；其余内网 |
| 地域 | 与业务用户就近 | 时区统一 `Asia/Shanghai` |

### 1.2 安全组入站（对标 AWS Security Group）

| 端口 | 协议 | 来源 | 用途 |
|------|------|------|------|
| 22 | TCP | 办公 IP / 堡垒机 | SSH（**勿**对 `0.0.0.0/0` 长期开放） |
| 80 | TCP | `0.0.0.0/0` 或 CDN | Nginx HTTP |
| 443 | TCP | `0.0.0.0/0` 或 CDN | Nginx HTTPS（配置证书后） |

**禁止对公网开放**：3306、6379、8848、8888、8090、21000（网关仅经 Nginx 反代，见 §8）。

### 1.3 从 AWS 迁移检查（T-1）

| # | 项 | ✓ |
|---|----|---|
| M1 | AWS 上 MySQL `moli` 库已 **mysqldump 备份** | |
| M2 | 记录 AWS `conf/moli-*.env` 中密码、Nacos namespace、Redis database | |
| M3 | 确认新 CVM 已绑定安全组 + 弹性 IP | |
| M4 | DNS（若有）计划切到新 IP 的 TTL 窗口 | |

## 2. CVM 首次初始化（Ubuntu · 用户 `ubuntu`）

腾讯云 Ubuntu 镜像**默认系统用户为 `ubuntu`**（已具备 `sudo`）。SSH：

```bash
ssh ubuntu@<公网IP>
# 或在控制台「登录」→ 标准方式，自动以 ubuntu 进入
```

登录后执行：

```bash
sudo apt update && sudo apt upgrade -y
sudo timedatectl set-timezone Asia/Shanghai

# 可选：主机名
sudo hostnamectl set-hostname moli-prod-tencent
```

应用与仓库放在 `/opt/moli-project-distribute`，属主设为 **`ubuntu`**（无需再建 `moli` 系统用户）：

```bash
sudo mkdir -p /opt/moli-project-distribute
sudo chown ubuntu:ubuntu /opt/moli-project-distribute
```

日常以 **`ubuntu`** 用户：`git pull`、改配置、跑 `moli-service.sh`；装系统包、改 Nginx 用 **`sudo`**。

### 2.2 可选：UFW（安全组已收紧时可开）


### 3.2 MySQL 8

Ubuntu 24.04（Noble）官方源里，`mysql-server` 是**元包**，依赖 **`mysql-server-8.0`**（当前约 8.0.36–8.0.46）。  
**不要**装 `mariadb-server`（那是 MariaDB，与项目契约「MySQL 8.x」不同）。

```bash
sudo apt install -y mysql-server
sudo systemctl enable mysql
sudo systemctl start mysql

# 安装后必做：确认是 8.0.x，而不是 MariaDB
mysql --version
# 期望类似：mysql  Ver 8.0.xx-0ubuntu0.24.04.x for Linux on x86_64 ((Ubuntu))

dpkg -l | grep -E 'mysql-server|mariadb'
# 期望看到 mysql-server-8.0，不应出现 mariadb-server
```

若 `mysql --version` **不是** `8.0` 开头，说明装错包或用了非官方源，应卸载后重装 `mysql-server-8.0`，或改用下方 Oracle 官方 APT 源。

建库（**只用 MySQL 账号 `root`**，密码写入 `moli-*.env`）。

| 名称 | 是什么 | 不是什么 |
|------|--------|----------|
| **`ubuntu`** | 腾讯云 CVM **操作系统**登录用户（SSH、`/opt` 文件属主） | ❌ MySQL 账号 |
| **`root`** | **MySQL 管理员**（建库、导库、应用连接都用它） | ❌ Linux 用户 |
| **`moli`** | **数据库名**（`CREATE DATABASE moli`） | ❌ MySQL 账号、❌ Linux 用户 |

Ubuntu 上 **新装的 MySQL 8**，`root@localhost` 默认插件是 **`auth_socket`**：只有 **`sudo mysql`** 能进，**`ubuntu` 用户直接 `mysql -u root -p` 会报 `ERROR 1698`**。必须先改密码认证。

**第 1 步**（`ubuntu` 用户，**不要**加 `-p`）：

```bash
sudo mysql -u root
```

**第 2 步**（在 `mysql>` 里执行）：

```sql
CREATE DATABASE IF NOT EXISTS moli
  DEFAULT CHARACTER SET utf8mb4
  COLLATE utf8mb4_unicode_ci;

-- 从 auth_socket 改为密码登录（ubuntu 用户与 Java 才能用 root + 密码连）
ALTER USER 'root'@'localhost' IDENTIFIED WITH mysql_native_password BY '请替换为强密码';
FLUSH PRIVILEGES;
EXIT;
```

**第 3 步**（退出后，**ubuntu** 用户验证，会提示输入密码）：

```bash
mysql -u root -p moli -e "SELECT 1"
```

若仍 1698，在 `sudo mysql` 里查插件是否改成功：

```sql
SELECT user, host, plugin FROM mysql.user WHERE user='root';
-- plugin 应为 mysql_native_password（或 caching_sha2_password），不能仍是 auth_socket
```

**不要**再建 `moli`@`localhost` 用户，**不要**重复 `GRANT`（`root` 本身已有全部权限）。

`moli-user-center/conf`、`moli-knowledge/conf`：

```bash
DB_HOST=localhost
SPRING_DATASOURCE_USERNAME=root
SPRING_DATASOURCE_PASSWORD=请替换为强密码
```

验证：

```bash
mysql -u root -p moli -e "SELECT 1"
```

导入全库（在 `ubuntu` 用户下执行，连的是 MySQL **`root`**）：

```bash
mysql -u root -p --default-character-set=utf8mb4 moli < /opt/moli-project-distribute/scripts/moli.sql
```

> **可选**：若你坚持把 `DB_HOST` 写成 `127.0.0.1`（TCP），MySQL 会再认一个 `root@127.0.0.1`，与 `root@localhost` 不是同一条记录，需额外执行：  
> `CREATE USER IF NOT EXISTS 'root'@'127.0.0.1' IDENTIFIED BY '同一密码';`  
> **默认请用 `DB_HOST=localhost`**，只维护 **`root@localhost` 即可。

**从 AWS 迁库**：

```bash
# AWS 上
mysqldump -u root -p --default-character-set=utf8mb4 --single-transaction moli > moli-prod.sql

# 腾讯云 CVM 上（ubuntu 用户执行，MySQL root 导入）
mysql -u root -p --default-character-set=utf8mb4 moli < moli-prod.sql
```

新环境全量（无 AWS 数据）见 §7。


```bash
cd /opt/moli-project-distribute
```

## 8. Nginx（腾讯云 CVM）

```bash
sudo tee /etc/nginx/sites-available/moli <<'EOF'
server {
    listen 80;
    server_name _;   # 有域名时改为 api.example.com 或主站域名

    location / {
        root /opt/moli-vue/dist;
        try_files $uri $uri/ /index.html;
        index index.html;
    }

    location /UserCenter/ {
        proxy_pass http://127.0.0.1:21000/UserCenter/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header Cookie $http_cookie;
    }
    location /KnowledgeServer/ {
        proxy_pass http://127.0.0.1:21000/KnowledgeServer/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header Cookie $http_cookie;
    }
    location /OrderServer/ {
        proxy_pass http://127.0.0.1:21000/OrderServer/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header Cookie $http_cookie;
    }
}
EOF

sudo ln -sf /etc/nginx/sites-available/moli /etc/nginx/sites-enabled/
sudo rm -f /etc/nginx/sites-enabled/default
sudo nginx -t && sudo systemctl reload nginx
```

HTTPS：在腾讯云申请证书（**SSL 证书服务** 或 **CDN** 托管），配置 `listen 443 ssl`；详见 `moli-knowledge/kb/wiki-moli/ops/nginx反向代理与前端部署指南.md`。

## 11. 上线冒烟

网关基址：`http://<CVM公网IP>:21000`（内网直连）或 `http://<域名>/`（经 Nginx）

| # | 检查 | 期望 |
|---|------|------|
| S1 | POST `/UserCenter/login` | 200，有 token |
| S3 | GET `/KnowledgeServer/kb/index?spaceId=...` + Authorization | 200 |

## 附录 A：腾讯云 / Ubuntu 常见问题

### `$'\r': command not found`（CRLF）

Windows 上传的 `.env` / `.sh` 带 CRLF：

```bash
cd /opt/moli-project-distribute
sed -i 's/\r$//' deploy/linux/*.sh
sed -i 's/\r$//' moli-knowledge/kb/tools/ci/run_sync.sh
sed -i 's/\r$//' moli-*/conf/moli-*.env
chmod +x deploy/linux/moli-service.sh
```

或：`sudo apt install -y dos2unix && dos2unix deploy/linux/*.sh moli-*/conf/moli-*.env`

### `ERROR 1698 (28000): Access denied for user 'root'@'localhost'`

**原因**：`root@localhost` 仍用 **`auth_socket`**，只允许 `sudo mysql` 进库；`ubuntu` 用户执行 `mysql -u root -p` 会被拒。

**处理**（按顺序，不要跳过 `sudo mysql`）：

```bash
sudo mysql -u root
```

```sql
ALTER USER 'root'@'localhost' IDENTIFIED WITH mysql_native_password BY '你的强密码';
FLUSH PRIVILEGES;
EXIT;
```

再测（**ubuntu** 用户，交互输入密码，避免命令行写密码触发 Warning）：

```bash
mysql -u root -p moli -e "SELECT 1"
```

`Using a password on the command line interface can be insecure` 只是警告；用 **`-p` 交互输入** 或写到 `moli-*.env` 给 Java 用即可，不要 `mysql -uroot -p你的密码` 写在同一行。

### `java not found`

```bash
which java
ls /usr/lib/jvm/
```

在 `conf/moli-*.env` 设置 §3.1 的 `JAVA_HOME`；`moli-service.sh` 会优先使用 `$JAVA_HOME/bin/java`。

### `1045 Access denied`（sync_to_db）

未 `source moli-knowledge.env` 时脚本默认 `root/12345678`。按 §9 加载 env 后再 Sync。

### 安全组已开 80 仍无法访问

检查：CVM 是否绑定弹性公网 IP、Nginx `systemctl status nginx`、UFW 是否拦截、`curl -I http://127.0.0.1`。

### 磁盘不足

`kb/raw` 图包约 12 MiB；**勿**上传整包 `wujinsen_markdown`。日志定期清理 `moli-*/logs/`。

## 14. 系统内一键部署（可选）

上线流程中的 **启停 / 上传 JAR / 前端 dist / nginx reload / 自定义 shell** 可在茉莉 **运营管理 → 部署中心** 完成（需先执行 `docs/sql/21_operation_ssh_deploy.sql`、**`22_operation_command_flex.sql`**，并在服务器台账配置 SSH 私钥）。

| 手工步骤（本文） | 系统内替代 |
|------------------|------------|
| scp JAR 到 `moli-*/` | 部署中心 → **手输路径**上传到 `.../moli-*/` + `restartService` 或 **custom** 后置 |
| scp 前端 dist | 上传到 `/opt/moli/frontend/dist/` + `nginxReload` 或 `unzipToDist` |
| `moli-service.sh start/stop` | 部署中心 → 选服务器 → 启停三件套（异步任务 + 日志） |
| 一次性远程命令 | 部署中心 → **远程命令**（或上传后 custom 后置） |

服务端需开启：`ops.deploy.enabled=true`、`ops.upload.enabled=true`、**`ops.command.enabled=true`**（远程命令/custom 后置）、`OPS_SECRET_KEY` 已配置。详见 [`docs/api/operation-deploy-api.md`](../docs/api/operation-deploy-api.md)。
