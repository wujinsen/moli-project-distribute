## 2. 上传到服务器

将内容同步到 **`/opt/moli-project-distribute`**。下面 **方式 A / 方式 B 二选一**，勿混用。

### 方式 A · 整仓 git pull（与 Git 目录一致）

适合 EC2 上 `git pull` 更新代码 + `kb/` + 在服务器上 `mvn package`。

```
/opt/moli-project-distribute/              ← Git 仓库根
├── deploy/
│   ├── linux/moli-service.sh
│   ├── user-center/application-pro.yml    ← 配置模板（首次复制到各服务目录）
│   ├── gateway/
│   └── knowledge/
├── moli-user-center/
│   ├── moli-user-center-server/target/moli-user-center-server-*.jar
│   ├── application-pro.yml                ← 运行时（从 deploy/user-center/ 复制）
│   └── conf/moli-user-center.env
├── moli-gateway/
│   ├── target/moli-gateway-*.jar
│   ├── application-pro.yml
│   └── conf/moli-gateway.env
├── moli-knowledge/
│   ├── moli-knowledge-server/target/moli-knowledge-server-*.jar
│   ├── kb/                                ← wiki 源；lint/sync 在 kb/ 下执行
│   ├── application-pro.yml
│   └── conf/moli-knowledge.env
```

**首次就位**（配置模板 → 运行时目录，只需做一次）：

```bash
cd /opt/moli-project-distribute

cp deploy/user-center/conf/moli-user-center.env moli-user-center/conf/

cp deploy/knowledge/conf/moli-knowledge.env moli-knowledge/conf/
chmod 600 moli-*/conf/*.env
```

`moli-service.sh` 会先在服务根目录找 JAR，找不到再查 `*/target/`（见脚本 `SVC_MAVEN_TARGET`）。

## 4. Wiki → MySQL 同步（有 wiki 变更时必做）

> **Sync 只写 markdown 进 MySQL**，不上传 png。插图见 **§4.3**。

### 4.1 前置：Python3 + pymysql（EC2 首次必做）

Amazon Linux 默认只有 **`python3`**，没有 `python`、也没有 pip。

```bash
sudo yum install -y python3-pip
python3 -m pip install -r /opt/moli-project-distribute/moli-knowledge/kb/tools/requirements-sync.txt
python3 -c "import pymysql; print('pymysql OK', pymysql.__version__)"
```

| 现象 | 处理 |
|------|------|
| `No module named pip` | 先 `yum install python3-pip`（AL2023 用 `dnf`） |
| `需要 pymysql`（sync-all 报） | 执行上面 `pip install -r .../requirements-sync.txt` |
| `python: command not found`（run_sync.sh） | 脚本已改为 `python3`；旧版可 `sed -i 's/\bpython /python3 /g' tools/ci/run_sync.sh` |
| `python3\r: No such file or directory`（lint.py） | Windows CRLF → `sed -i 's/\r$//' tools/lint.py` 或 git 拉 LF 版 |

### 4.2 执行 Sync

> **常见报错**：直接跑 `python3 tools/sync_to_db.py ...` **不传 DB 参数**时，脚本默认 `root` / `12345678`（开发机），生产会 **`1045 Access denied`**。  
> **必须先**加载 `moli-knowledge/conf/moli-knowledge.env`，与 knowledge-server 使用**同一套** `SPRING_DATASOURCE_*`。

#### 4.2.1 加载 DB 账号（每次 Sync 前）

```bash
cd /opt/moli-project-distribute/moli-knowledge/kb

set -a
source <(sed 's/\r$//' /opt/moli-project-distribute/moli-knowledge/conf/moli-knowledge.env)
set +a

export KB_SYNC_HOST="${DB_HOST:-127.0.0.1}"
export KB_SYNC_PORT="${DB_PORT:-3306}"
export KB_SYNC_USER="${SPRING_DATASOURCE_USERNAME}"
export KB_SYNC_PASSWORD="${SPRING_DATASOURCE_PASSWORD}"
export KB_SYNC_DB="${DB_NAME:-moli}"
export KB_SYNC_PYTHON=python3
```

#### 4.2.2 验证 MySQL（建议，避免白跑 Sync）

```bash
mysql -h"${KB_SYNC_HOST}" -P"${KB_SYNC_PORT}" \
  -u"${KB_SYNC_USER}" -p"${KB_SYNC_PASSWORD}" \
  "${KB_SYNC_DB}" -e "SELECT 1"
```

若此处仍 `1045`，说明 **env 与 MySQL 不一致**（用户名/密码/权限），先修正 `moli-knowledge.env` 或 MySQL 用户，再 Sync。

#### 4.2.3 预览（不写库）

```bash
bash tools/ci/run_sync.sh dry-run-all
```

#### 4.2.4 写库

**三空间一起**（日常默认）：

```bash
bash tools/ci/run_sync.sh sync-all
```

**仅茉莉系统手册**（只改了 `wiki-moli/`，如概要设计导入）：

```bash
python3 tools/sync_to_db.py \
  --wiki-dir wiki-moli \
  --space moli-ops-manual \
  --host "${KB_SYNC_HOST}" \
  --port "${KB_SYNC_PORT}" \
  --user "${KB_SYNC_USER}" \
  --password "${KB_SYNC_PASSWORD}" \
  --db "${KB_SYNC_DB}"
```

成功时终端会打印 insert/update 的 slug 列表；失败不应出现 `pymysql.err.OperationalError: (1045, ...)`。

**lint 与 Sync 关系**：

| 项 | 说明 |
|----|------|
| `wiki`（enterprise-kb） | 建议 `python3 tools/lint.py --strict --wiki-dir wiki` |
| `wiki-moli` | 常有历史 WARN/断链，**`--strict` 失败不挡 Sync** |
| **Sync 不检查 lint** | dry-run 通过后可直接 `sync-all` |

在 **`kb/` 根目录**执行（不是 `tools/` 子目录）；`--wiki-dir wiki` 相对 `kb/`。

### 4.3 生产插图包（T22 · 与 Sync **分开**必做）

**勿**上传整包 `kb/raw/wujinsen_markdown/`（约 0.29 GiB）。B/D 档 hub 插图只需 **212 张 png（约 12 MiB）**。

## 10. 配置对照

### 10.1 目录与文件

| 服务 | APP_HOME | env 文件 | 业务配置 |
|------|----------|----------|----------|
| user-center | `.../moli-user-center` | `conf/moli-user-center.env` | `application-pro.yml` |
| gateway | `.../moli-gateway` | `conf/moli-gateway.env` | `application-pro.yml` |
| knowledge | `.../moli-knowledge` | `conf/moli-knowledge.env` | `application-pro.yml` |

**两层配置（勿混淆）**：

| 层 | 位置 | 作用 |
|----|------|------|
| **bootstrap**（在 JAR 内 `bootstrap.yml`，pro 段） | 读 env 里 `NACOS_*` | Nacos **服务注册发现** |
| **application-pro.yml**（JAR 旁外挂） | 端口、路由、MySQL、Redis 等 | **业务与网关路由** |

启动命令由脚本注入：`--spring.config.additional-location=file:./application-pro.yml`

### 10.2 env 常用键

| 键 | 说明 |
|----|------|
| `MOLI_DEPLOY_ROOT` / `MOLI_ROOT` / `APP_HOME` | 部署根；**脚本会强制** `APP_HOME=/opt/moli-project-distribute/moli-<服务>`（env 里旧 `/opt/moli/*` 会被忽略） |
| `SPRING_PROFILES_ACTIVE=pro` | 必须 |
| `NACOS_SERVER_ADDR` | Nacos HTTP 地址，如 `http://127.0.0.1:8848` |
| `NACOS_NAMESPACE` | 生产命名空间 ID 或名（如 `prod`），**各服务必须一致** |
| `NACOS_USERNAME` / `NACOS_PASSWORD` | Nacos 登录（bootstrap pro 用） |
| `SPRING_DATASOURCE_*` | user-center / knowledge MySQL |
| `SSO_SHARED_SECRET` | user-center 必改 |
| `KB_WIKI_ROOT` | knowledge wiki 源，默认 `.../moli-knowledge/kb` |
| `KB_RAW_ROOT` | **B/D 档插图**读盘路径，默认 `.../moli-knowledge/kb/raw`（见 §4.3） |
| `SERVER_PORT` | gateway 默认 `21000` |

## 附录 A：EC2 / Amazon Linux 常见问题

### `$'\r': command not found` / `bash\r: No such file or directory`

**原因**：Windows 编辑或上传的文件为 CRLF。`.env` 与 **`deploy/linux/*.sh`** 都会中招；后者会导致 shebang 变成 `bash\r`，脚本根本跑不起来。

**一次性修复（EC2 上执行）**：

```bash
cd /opt/moli-project-distribute
sed -i 's/\r$//' deploy/linux/*.sh
sed -i 's/\r$//' moli-knowledge/kb/tools/deploy_raw_assets.sh
sed -i 's/\r$//' moli-knowledge/kb/tools/ci/run_sync.sh
sed -i 's/\r$//' moli-*/conf/moli-*.env
chmod +x deploy/linux/moli-service.sh
```

或：

```bash
sudo yum install -y dos2unix
dos2unix deploy/linux/*.sh moli-*/conf/moli-*.env
```

`moli-service.sh` 加载 `.env` 时会自动 strip `\r`，但 **脚本自身必须是 LF**（需 `sed`/`dos2unix` 或 git pull 后 `--renormalize` 的版本）。

### `java not found`

脚本找不到的是 **`java` 命令在 PATH 里**，不是说你没装 JDK。常见原因：JDK 在 `/usr/lib/jvm/...` 但非交互 shell 的 PATH 里没有。

```bash
which java
ls /usr/lib/jvm/
java -version
```

在 `conf/moli-*.env` 里指向**已有** JDK（与线上一致）：

```bash
JAVA_HOME=/usr/lib/jvm/你的jdk目录名
```

新版脚本也会自动扫描 `/usr/lib/jvm/*`。

### `/usr/bin/python3: No module named pip`

**原因**：EC2 最小镜像只装 `python3`，未装 `python3-pip`。

```bash
# 先装 pip（Amazon Linux 2）
sudo yum install -y python3-pip

# Amazon Linux 2023 用 dnf
# sudo dnf install -y python3-pip

python3 -m pip --version
python3 -m pip install -r /opt/moli-project-distribute/moli-knowledge/kb/tools/requirements-sync.txt
```

若 `yum` 源里没有 `python3-pip`，可 bootstrap：

```bash
curl -sS https://bootstrap.pypa.io/get-pip.py -o /tmp/get-pip.py
python3 /tmp/get-pip.py --user
python3 -m pip install --user -r /opt/moli-project-distribute/moli-knowledge/kb/tools/requirements-sync.txt
```

### `python: command not found`（run_sync.sh / sync_to_db）

EC2 无 `python` 命令，只有 **`python3`**。`tools/ci/run_sync.sh` 已默认 `python3`；手工调用也请用 `python3 tools/sync_to_db.py ...`。

### `1045 Access denied for user 'root'@'localhost'`（sync_to_db）

| 原因 | 处理 |
|------|------|
| 未加载 env，用了默认 `root/12345678` | 按 **§4.2.1** `source moli-knowledge.env`，Sync 时带 `--user/--password`（§4.2.4） |
| env 账号与 MySQL 不一致 | 改 `SPRING_DATASOURCE_USERNAME/PASSWORD` 或建库用户；先用 §4.2.2 `mysql ... SELECT 1` 验证 |
| 密码含特殊字符 | 使用 `"${SPRING_DATASOURCE_PASSWORD}"`，勿手敲 |

### `lint.py --strict` 失败但能否 Sync？

**可以**。`sync-all` 不依赖 lint 退出码。`wiki-moli` 常有断链/孤儿 WARN；**enterprise-kb `wiki/` 建议 strict 过**，但不挡发布。

### `deploy_raw_assets.sh`：`set: pipefail` / `target raw root missing`

| 报错 | 处理 |
|------|------|
| `pipefail` / `$'\r'` | Windows 上传 CRLF → `sed -i 's/\r$//' deploy_raw_assets.sh` |
| `target raw root missing`（旧脚本） | `mkdir -p .../kb/raw` 后重跑；新版脚本会自动创建 |

### Web「图片加载失败」但 Sync 已成功

Sync **只同步 markdown**。B/D 档图在 **`kb/raw/`**（§4.3 最小 tar 包），annex 图在 **`kb/wiki/**/.assets/`**。缺盘文件会 404，与 MySQL 无关。

## 7. 运维台 · 部署中心启用（Phase R0）

> 部署中心在 **user-center** 进程内；默认 **三开关全关**，菜单可见但启停/上传/命令会报业务码 **10106/10108** 或参数错误。  
> HTTP 契约：[`docs/api/operation-deploy-api.md`](../docs/api/operation-deploy-api.md) · 前端：[`operation-frontend.md`](../docs/api/operation-frontend.md) §13

### 7.1 生产环境变量（`moli-user-center`）

在 `moli-user-center/application-pro.yml` 或环境变量中设置（**勿提交 Git 明文密钥**）：

```yaml
ops:
  secret:
    key: ${OPS_SECRET_KEY}              # 必填：SSH/平台凭据 AES
  deploy:
    enabled: true
    allow-local: false                  # 生产必须 false；所有 API 须带 serverId
    status-sync-mode: ssh               # deploy_running 与远程 status 一致
    deploy-root: /opt/moli-project-distribute
  upload:
    enabled: true                       # 需要 jar/静态包发布时
  command:
    enabled: true                       # 需要 custom 后置命令 / 远程命令时
  health:
    probe-enabled: true                 # 可选：定时 TCP 探活 + deploy_running 同步
```

| 变量 | 说明 |
|------|------|
| `OPS_SECRET_KEY` | 与 `ops.secret.key` 等价；未设则 SSH 加密字段不可用 |
| `OPS_DEPLOY_ENABLED` | 启停 restart 后置动作 |
| `OPS_DEPLOY_ALLOW_LOCAL` | 默认 `false`；仅 dev Linux 可 `true` |
| `OPS_DEPLOY_STATUS_SYNC_MODE` | `ssh`（推荐）· `local` · `off` |
| `OPS_UPLOAD_ENABLED` / `OPS_COMMAND_ENABLED` | 上传与远程命令 |

**serviceKey 范围**：`application.yml` 中 `ops.deploy.services` 含 `user-center` · `gateway` · `knowledge` · **`order`** · **`ai`**。  
远程启停依赖目标机 `deploy/linux/moli-service.sh`；当前脚本仅实现前三者，**order/ai 用于台账映射与 presets 下拉**，扩展脚本前勿在生产对该二键执行 deploy task。

### 7.3 权限（角色需含下列 perm_code）

| 能力 | perm_code |
|------|-----------|
| 台账 / 探活 / status 只读 | `operation:server:list` 等 |
| 远程启停 | `operation:deploy:exec` |
| 文件上传 | `operation:file:upload` |
| 远程命令 | `operation:command:exec` |
| 查看平台密码明文 | `operation:secret:view` |

发版后相关用户 **重新登录** 以刷新 Shiro 权限缓存。

### 7.4 冒烟（生产）

```bash
# 1) 远程 status（须 serverId）
curl -H "Authorization: Bearer <token>" \
  "https://<host>/UserCenterServer/operation/deploy/user-center/status?serverId=204"

# 2) probe-all 异步 → 返回 taskId
curl -X POST -H "Authorization: Bearer <token>" \
  "https://<host>/UserCenterServer/operation/health/probe-all"

# 3) presets 含 serviceKeys（含 order/ai 时共 5 项）
curl -H "Authorization: Bearer <token>" \
  "https://<host>/UserCenterServer/operation/deploy/presets?serverId=204"
```

### 7.5 已有库：清理演示平台明文密码

若库中仍有种子 `change-me`，在运维台补录真实凭据前执行一次：

```sql
UPDATE operation_platform_info SET password = NULL WHERE password = 'change-me';
```

新装库执行 `scripts/moli.sql` 后平台密码字段已为 `NULL`，须通过 UI 录入并加密存储。
