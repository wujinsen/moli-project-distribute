# Moli 生产上线流程（AWS · Amazon Linux / EC2）

> **适用**：AWS EC2 · **Amazon Linux 2023**（验证：`dnf` · 用户 `ec2-user`）  
> **亦参考**：Amazon Linux 2（`yum` 替代 `dnf`）  
> **不适用**：腾讯云 CVM · Ubuntu —— 见 [`腾讯云上线流程.md`](腾讯云上线流程.md)  
> **工程 Runbook 索引**：[`docs/ops/v1-release-runbook.md`](../docs/ops/v1-release-runbook.md)  
> **仅装基础环境**（复制命令 + 自检）：[`docs/ops/aws-ec2-bootstrap.md`](../docs/ops/aws-ec2-bootstrap.md)  
> **敏感文件**：`application-pro.yml` / `conf/moli-*.env` **不提交 Git**；模板见 `deploy/linux/moli-*.env.example`  
> **知识库专项**（T20 / 概要设计）：[`docs/ops/kb-t20-design-docs-release.md`](../docs/ops/kb-t20-design-docs-release.md)

**部署根目录**：`/opt/moli-project-distribute`（与腾讯云版一致，便于迁移）  
**EC2 默认登录用户**：`ec2-user`（Amazon Linux 镜像自带，本文后续命令均在此用户下执行）  
**本批服务**：user-center · knowledge · gateway（v1 最小三件套）

## 0. 与腾讯云版差异速查

| 项 | AWS（本文） | 腾讯云（[`腾讯云上线流程.md`](腾讯云上线流程.md)） |
|----|-------------|-----------------------------------------------------|
| 计算 | **EC2** | CVM |
| 防火墙 | **Security Group** | 安全组 + 可选 UFW |
| 系统镜像 | **Amazon Linux 2 / 2023** | Ubuntu 22.04 / 24.04 |
| 包管理 | **`dnf`** / `yum` | **`apt`** |
| JDK 11 | **Amazon Corretto**（`java-11-amazon-corretto`） | OpenJDK 11 / Temurin 11 |
| `JAVA_HOME` 示例 | `/usr/lib/jvm/java-11-amazon-corretto` | `/usr/lib/jvm/java-11-openjdk-amd64` |
| MySQL 8 | **官方 community 源**（AL 默认源常为 MariaDB） | `mysql-server-8.0` |
| Redis | 包名 **`redis6`** · CLI **`redis6-cli`** | `redis-server` · `redis-cli` |
| Redis 配置路径 | **`rpm -ql redis6 \| grep conf`**（非 `/etc/redis6/redis.conf`） | `/etc/redis/redis.conf` |
| Python pip | `dnf install python3-pip` | `apt install python3-pip` |
| Nginx 站点配置 | **`/etc/nginx/conf.d/moli.conf`** | `/etc/nginx/sites-available/moli` |
| 代码上传 | EC2 **`git pull`** / scp | CVM git pull / SCP / SFTP |
| 系统登录用户 | **`ec2-user`** | **`ubuntu`** |
| HTTPS 常见方案 | **Cloudflare 橙云 + Flexible SSL**（源站只 listen 80） | 腾讯云证书 / CDN |

> **勿混淆**：**`ec2-user`** = 服务器 OS 用户 · **`root`**（或 `moli`）= MySQL 账号 · **`moli`** = 库名（见 §3.2）

**业务逻辑、目录布局、启停脚本、DB/Sync/冒烟** 与腾讯云版相同；仅 **OS 安装命令、防火墙、JDK/Redis 路径** 按本文执行。

## 1. AWS EC2 资源规划

### 1.1 推荐规格（单机 v1 最小）

| 资源 | 建议 | 说明 |
|------|------|------|
| EC2 | 4 vCPU · 8 GiB 起 | user-center + knowledge + gateway + MySQL + Redis + Nacos |
| 系统盘 | 50 GiB SSD 起 | 含 `kb/`、日志、MySQL 数据 |
| 弹性 IP | 绑定实例 | 仅 **80/443** 对公网；其余内网 |
| 地域 | 与业务用户就近 | 时区统一 `Asia/Shanghai` |

### 1.2 Security Group 入站（对标腾讯云安全组）

| 端口 | 协议 | 来源 | 用途 |
|------|------|------|------|
| 22 | TCP | 办公 IP / VPN | SSH（**勿**对 `0.0.0.0/0` 长期开放） |
| 80 | TCP | `0.0.0.0/0` 或 Cloudflare | Nginx HTTP（**Cloudflare 橙云回源必需**） |
| 443 | TCP | `0.0.0.0/0` | 直连 HTTPS（若不用 Cloudflare 终结 TLS） |

**禁止对公网开放**：3306、6379、8848、8888、8090、21000（网关仅经 Nginx 反代，见 §8）。

### 1.3 上线前检查（T-1）

| # | 项 | ✓ |
|---|----|---|
| P1 | MySQL `moli` 库已 **mysqldump 备份**（若已有数据） | |
| P2 | 记录 `conf/moli-*.env` 中密码、Nacos namespace、Redis database | |
| P3 | EC2 已绑定弹性 IP + Security Group | |
| P4 | DNS（Cloudflare 等）计划切流 / TTL 窗口 | |
| P5 | 完成 [`docs/ops/production-checklist.md`](../docs/ops/production-checklist.md) | |

## 3. 基础软件安装（JDK 11 · MySQL 8 · Nginx · Redis · Nacos）

> **仅装环境、尚未部署应用？** 逐步复制 + 自检：[`docs/ops/aws-ec2-bootstrap.md`](../docs/ops/aws-ec2-bootstrap.md)

**推荐顺序**：JDK 11 → MySQL 8 → Nginx → Redis → Nacos → Python3/pymysql

### 3.0 装完快速自检（ec2-user）

```bash
java -version 2>&1 | head -1
mysql --version
redis6-cli ping
nginx -v 2>&1
systemctl is-active mysqld redis6 nginx
mysql -u root -p moli -e "SELECT 1"   # 已建库且 root 已改密码后
```

期望：Java **11** · MySQL **8.0**（非 MariaDB）· Redis **`PONG`** · 三个 service **`active`**。

| 常见误操作 | 处理 |
|------------|------|
| `apt: command not found` | 用 **`dnf`**，勿用 Ubuntu 命令 |
| `redis-cli: command not found` | 用 **`redis6-cli`**（§3.4） |
| `redis6` inactive (dead) | `sudo systemctl enable --now redis6` |

### 3.1 JDK 11（Amazon Corretto）

```bash
sudo dnf install -y java-11-amazon-corretto-devel
java -version
ls -d /usr/lib/jvm/java-11-amazon-corretto
```

**写入 env 的 `JAVA_HOME`**（三服务一致）：

```bash
JAVA_HOME=/usr/lib/jvm/java-11-amazon-corretto
```

> 腾讯云 OpenJDK 路径 **勿**照抄；见附录 A `java not found`。

### 3.2 MySQL 8

Amazon Linux **默认源不含 MySQL 8**（常见为 MariaDB）。须走 **MySQL 官方 community 源**，完整命令见 [`aws-ec2-bootstrap.md` §3.2](../docs/ops/aws-ec2-bootstrap.md)。

关键一步（AL2023 常见坑）：

```bash
sudo sed -i 's/$releasever/9/g' /etc/yum.repos.d/mysql-community.repo
sudo dnf makecache
sudo dnf install -y mysql-community-server
sudo systemctl enable --now mysqld
mysql --version
# 期望：mysql  Ver 8.0.xx ...
```

| 名称 | 是什么 | 不是什么 |
|------|--------|----------|
| **`ec2-user`** | EC2 **操作系统**登录用户 | ❌ MySQL 账号 |
| **`root`**（或自建 **`moli`**） | **MySQL 账号** | ❌ Linux 用户 |
| **`moli`** | **数据库名** | ❌ 与账号同名时易混 |

建库示例（**`root` + 密码**，与多数个人 env 一致）：

```sql
CREATE DATABASE IF NOT EXISTS moli
  DEFAULT CHARACTER SET utf8mb4
  COLLATE utf8mb4_unicode_ci;
-- 首次 root 密码见 /var/log/mysqld.log 临时密码，或 mysql_secure_installation
```

`moli-user-center/conf`、`moli-knowledge/conf`：

```bash
DB_HOST=127.0.0.1
SPRING_DATASOURCE_USERNAME=root
SPRING_DATASOURCE_PASSWORD=请替换为强密码
```

验证：

```bash
mysql -u root -p moli -e "SELECT 1"
```

> 若使用 **`moli`@`localhost` 专用账号**，三份 env 的 `SPRING_DATASOURCE_*` 须与建库用户一致；见 bootstrap §3.2 的 `CREATE USER 'moli'@'localhost'` 示例。

### 3.3 Nginx

```bash
sudo dnf install -y nginx
sudo systemctl enable --now nginx
sudo nginx -t
curl -I http://127.0.0.1
```

站点反代见 **§8**。**443** 留给 Nginx；勿让 `sshd` 长期占用 443。

### 3.4 Redis 6+（v1 必需）

Amazon Linux 2023 包名为 **`redis6`**；安装后默认 **disabled**，须显式启用。

```bash
sudo dnf install -y redis6
sudo systemctl enable --now redis6
systemctl is-active redis6
redis6-cli ping
# 期望：PONG
```

**查配置文件**（**`/etc/redis6/redis.conf` 通常不存在**）：

```bash
rpm -ql redis6 | grep '\.conf$'
# 常见：/etc/redis/redis.conf
```

**生产设密码**（与 `SPRING_REDIS_PASSWORD` 一致）：

```bash
sudo grep -n requirepass /etc/redis/redis.conf
sudo vi /etc/redis/redis.conf    # requirepass 你的强密码
sudo systemctl restart redis6
redis6-cli -a 你的强密码 ping
```

应用 env（改完 **restart** Java 服务）：

- `moli-user-center/conf/moli-user-center.env`
- `moli-knowledge/conf/moli-knowledge.env`

```bash
SPRING_REDIS_HOST=127.0.0.1
SPRING_REDIS_PORT=6379
SPRING_REDIS_PASSWORD=你的强密码
SPRING_REDIS_DATABASE=1
```

可选：`sudo ln -sf /usr/bin/redis6-cli /usr/local/bin/redis-cli`

### 3.5 Nacos 2.x（v1 必需）

```bash
cd /opt
sudo wget https://github.com/alibaba/nacos/releases/download/2.0.3/nacos-server-2.0.3.tar.gz
sudo tar -xzf nacos-server-2.0.3.tar.gz
sudo chown -R ec2-user:ec2-user /opt/nacos

export JAVA_HOME=/usr/lib/jvm/java-11-amazon-corretto
cd /opt/nacos/bin
sh startup.sh -m standalone
```

控制台：`http://127.0.0.1:8848/nacos`（**勿**公网开放 8848）。创建命名空间 **`prod`**，与各服务 `NACOS_NAMESPACE=prod` 一致。

### 3.6 Python3 + pymysql（Wiki Sync 必需）

```bash
sudo dnf install -y python3-pip
python3 -m pip install -r /opt/moli-project-distribute/moli-knowledge/kb/tools/requirements-sync.txt
python3 -c "import pymysql; print('pymysql OK', pymysql.__version__)"
```

若 `dnf` 无 pip，见 [`aws-ec2-bootstrap.md` §3.6](../docs/ops/aws-ec2-bootstrap.md) 的 get-pip 备选。

## 6. 上传到 EC2

将内容同步到 **`/opt/moli-project-distribute`**。**方式 A / 方式 B 二选一**，勿混用（与腾讯云 §6 相同）。

### 方式 A · 整仓 git pull

适合 EC2 上 `git pull` 更新代码 + `kb/`；可选在 EC2 上 `mvn package`。

```
/opt/moli-project-distribute/              ← Git 仓库根
├── deploy/
├── moli-user-center/
│   ├── moli-user-center-server/target/*.jar   ← 方式 A：JAR 可在 target/
│   ├── application-pro.yml
│   └── conf/moli-user-center.env
├── moli-gateway/
├── moli-knowledge/
│   ├── moli-knowledge-server/target/*.jar
│   └── kb/                                ← wiki 源；sync 在 kb/ 下执行
└── scripts/、docs/、…（整仓源码亦在此，运行时只跑 JAR）
```

**首次 clone**（整仓含 `moli-knowledge/kb/`）：

```bash
cd /opt/moli-project-distribute

ssh-keygen -t ed25519 -C "ec2-moli" -f ~/.ssh/id_ed25519 -N ""
cat ~/.ssh/id_ed25519.pub
# → GitHub Settings → Deploy keys（只读）或账号 SSH keys

ssh -T git@github.com
# 首次 fingerprint → 输入 yes
# 成功：Hi xxx! You've successfully authenticated...

git clone git@github.com:wujinsen/moli-project-distribute.git .
git checkout main
```

**日常更新**：

```bash
cd /opt/moli-project-distribute
git pull origin main
```

| 现象 | 处理 |
|------|------|
| GitHub SSH 首次连 | 指纹 `SHA256:+DiY3wvvV6TuJJhbpZisF/zLDA0zPMSvHdkr4UvCOqU` → **`yes`** |
| `Permission denied (publickey)` | EC2 公钥未加到 GitHub |
| 本地冲突 | `git stash` → `git pull` → `git stash pop` |

**`scripts/moli.sql` 与 Git**：仓库内多为 **小体积基线**；本地 Navicat 全库导出（常 **数十 MB**）**不会**随 `git pull` 到 EC2：

```powershell
scp D:\work\moli_project\moli-project-distribute\scripts\moli.sql ec2-user@<IP>:/opt/moli-project-distribute/scripts/
```

或：导入 Git 基线 + `docs/sql` 增量 + §9 **sync-all**。

**首次就位**（配置模板 → 运行时目录，只需一次）：

```bash
cd /opt/moli-project-distribute
mkdir -p moli-user-center/conf moli-gateway/conf moli-knowledge/conf
cp deploy/user-center/application-pro.yml moli-user-center/
cp deploy/user-center/conf/moli-user-center.env moli-user-center/conf/
cp deploy/gateway/application-pro.yml moli-gateway/
cp deploy/gateway/conf/moli-gateway.env moli-gateway/conf/
cp deploy/knowledge/application-pro.yml moli-knowledge/
cp deploy/knowledge/conf/moli-knowledge.env moli-knowledge/conf/
chmod 600 moli-*/conf/*.env
```

`moli-service.sh` 会先在服务根目录找 JAR，找不到再查 `*/target/`。

### 方式 B · 扁平目录（rsync/scp，换包推荐）

只上传 JAR + 配置 + `kb/` + 脚本，**不含** Maven 源码树。

本地 PowerShell / Git Bash：

```powershell

```

| 本地 | EC2 |
|------|-----|
| `deploy/user-center/application-pro.yml` | `moli-user-center/application-pro.yml` |
| `deploy/user-center/conf/moli-user-center.env` | `moli-user-center/conf/moli-user-center.env` |
| `deploy/gateway/*` | `moli-gateway/` |
| `deploy/knowledge/*` | `moli-knowledge/` |
| JAR | 各 `moli-*/` **根目录**（非 `target/`） |
| `moli-knowledge/kb/` | `moli-knowledge/kb/` |
| `deploy/linux/moli-service.sh` | `deploy/linux/moli-service.sh` |

大文件 `kb/` 建议 `rsync -avz -e ssh ec2-user@<IP>:...` 或 tar 包上传。

## 8. Nginx（AWS EC2）

Amazon Linux 站点配置放在 **`/etc/nginx/conf.d/`**（与 Ubuntu `sites-available` 不同）。

### 8.1 茉莉主站 + 网关反代（示例）

```bash
sudo tee /etc/nginx/conf.d/moli.conf <<'EOF'
server {
    listen 80;
    server_name moli-ui.example.com;   # 改为你的域名

    root /opt/moli/frontend/dist;
    try_files $uri $uri/ /index.html;
    index index.html;

    location /UserCenter/ {
        proxy_pass http://127.0.0.1:21000/UserCenter/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header Cookie $http_cookie;
    }
    location /KnowledgeServer/ {
        proxy_pass http://127.0.0.1:21000/KnowledgeServer/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header Cookie $http_cookie;
    }
}
EOF

sudo nginx -t && sudo systemctl reload nginx
curl -I http://127.0.0.1
```

多站点（静态 Astro 等）可同文件追加多个 `server { ... }` 块；完整范例见 `moli-knowledge/kb/wiki-moli/ops/nginx反向代理与前端部署指南.md`。

### 8.2 Cloudflare + 源站只开 80

| 项 | 说明 |
|----|------|
| DNS | 橙云（Proxied）指向 EC2 弹性 IP |
| SSL/TLS | **Flexible**（访客 HTTPS → Cloudflare → 源站 **HTTP:80**） |
| Security Group | 必须开放 **80**（仅开 443 时橙云回源会失败） |
| 源站 Nginx | `listen 80` 即可；无需在 EC2 装 origin 证书 |

直连 HTTPS（无 Cloudflare）须在 EC2 配置 `listen 443 ssl` + 证书。

配置文件权限建议 **`644`**、`root:root`（`moli.conf`）。

## 9. Wiki → MySQL 同步

> **Sync 只写 markdown 进 MySQL**，不上传 png。插图见 **§9.2**。

与腾讯云 §9 相同；**差异仅 pip 安装**（§3.6）。

```bash
cd /opt/moli-project-distribute/moli-knowledge/kb

set -a
source <(sed 's/\r$//' /opt/moli-project-distribute/moli-knowledge/conf/moli-knowledge.env)
set +a

export KB_SYNC_HOST="${DB_HOST:-127.0.0.1}"
export KB_SYNC_PORT="${DB_PORT:-3306}"
export KB_SYNC_USER="${SPRING_DATASOURCE_USERNAME}"
export KB_SYNC_PASSWORD="${SPRING_DATASOURCE_PASSWORD}"
export KB_SYNC_DB="${DB_NAME:-moli}"
export KB_SYNC_PYTHON=python3

mysql -h"${KB_SYNC_HOST}" -P"${KB_SYNC_PORT}" \
  -u"${KB_SYNC_USER}" -p"${KB_SYNC_PASSWORD}" \
  "${KB_SYNC_DB}" -e "SELECT 1"

bash tools/ci/run_sync.sh dry-run-all
```

## 13. 配置对照

与腾讯云 §13 相同。AWS **务必修改**：

| 键 | AWS 说明 |
|----|----------|
| `JAVA_HOME` | `/usr/lib/jvm/java-11-amazon-corretto`（§3.1） |
| `DB_HOST` | 本机 `127.0.0.1` 或 RDS 内网地址 |
| `SPRING_REDIS_*` | **各服务 host/port/password/database 必须一致** |
| `NACOS_SERVER_ADDR` | 本机 `http://127.0.0.1:8848` 或托管 Nacos |

### 13.1 目录与两层配置

| 服务 | APP_HOME | env 文件 | 业务配置 |
|------|----------|----------|----------|
| user-center | `.../moli-user-center` | `conf/moli-user-center.env` | `application-pro.yml` |
| gateway | `.../moli-gateway` | `conf/moli-gateway.env` | `application-pro.yml` |
| knowledge | `.../moli-knowledge` | `conf/moli-knowledge.env` | `application-pro.yml` |

| 层 | 位置 | 作用 |
|----|------|------|
| **bootstrap**（JAR 内） | 读 env 里 `NACOS_*` | Nacos 注册发现 |
| **application-pro.yml**（JAR 旁） | MySQL、Redis、端口、路由 | 业务与网关 |

**改 Nacos → 改 `conf/moli-*.env`**，不必重打 JAR。

### 13.2 env 常用键

| 键 | 说明 |
|----|------|
| `MOLI_ROOT` / `APP_HOME` | 部署根；脚本强制 `APP_HOME=.../moli-<服务>` |
| `SPRING_PROFILES_ACTIVE=pro` | 必须 |
| `NACOS_SERVER_ADDR` / `NACOS_NAMESPACE` | 各服务 **namespace 一致** |
| `SPRING_DATASOURCE_*` | user-center / knowledge MySQL |
| `SPRING_REDIS_*` | 会话共享，password 与 Redis `requirepass` 一致 |
| `SSO_SHARED_SECRET` | user-center 必改 |
| `KB_WIKI_ROOT` / `KB_RAW_ROOT` | knowledge wiki 源 / B-D 插图盘路径 |
| `SERVER_PORT` | gateway 默认 `21000` |

## 附录 A：EC2 / Amazon Linux 常见问题

### Redis：`inactive (dead)` / `redis-cli: command not found` / 找不到 `redis.conf`

| 现象 | 原因 | 处理 |
|------|------|------|
| `redis6` **inactive (dead)** | 仅 `dnf install` 未启服务 | `sudo systemctl enable --now redis6` |
| `redis-cli: command not found` | CLI 名为 **`redis6-cli`** | `redis6-cli ping` |
| `/etc/redis6/redis.conf: No such file` | 配置路径不同 | `rpm -ql redis6 \| grep '\.conf$'` |

详见 §3.4 · [`aws-ec2-bootstrap.md` §3.4](../docs/ops/aws-ec2-bootstrap.md)。

### GitHub SSH 首次连接

指纹 `SHA256:+DiY3wvvV6TuJJhbpZisF/zLDA0zPMSvHdkr4UvCOqU` → 输入 **`yes`**。`Permission denied (publickey)` → 添加 Deploy Key。见 §6 方式 A。

### `$'\r': command not found`（CRLF）

```bash
cd /opt/moli-project-distribute
sed -i 's/\r$//' deploy/linux/*.sh
sed -i 's/\r$//' moli-knowledge/kb/tools/ci/run_sync.sh
sed -i 's/\r$//' moli-knowledge/kb/tools/deploy_raw_assets.sh
sed -i 's/\r$//' moli-*/conf/moli-*.env
chmod +x deploy/linux/moli-service.sh
```

或：`sudo dnf install -y dos2unix && dos2unix deploy/linux/*.sh moli-*/conf/moli-*.env`

### `java not found`

```bash
which java
ls /usr/lib/jvm/
```

在 `conf/moli-*.env` 设置 §3.1 的 `JAVA_HOME`。

### `/usr/bin/python3: No module named pip`

```bash
sudo dnf install -y python3-pip
python3 -m pip install -r /opt/moli-project-distribute/moli-knowledge/kb/tools/requirements-sync.txt
```

### `1045 Access denied`（sync_to_db / MySQL）

未 `source moli-knowledge.env` 时脚本默认 `root/12345678`。按 §9 加载 env；先用 `mysql ... SELECT 1` 验证账号。

### MySQL 装成 MariaDB / community 源无包

走 §3.2 + [`aws-ec2-bootstrap.md` §3.2](../docs/ops/aws-ec2-bootstrap.md)：`mysql-community-server` + `sed ... releasever/9`。

### 安全组已开 443 仍无法 HTTPS（Cloudflare 橙云）

须同时开放 **80**；Cloudflare SSL 模式 **Flexible**；源站 Nginx `listen 80`。`curl -I http://127.0.0.1` 应先 200。

Sync 只进 markdown。B/D 图在 `kb/raw/`（§9.1）；annex 图在 `kb/wiki/**/.assets/`。

### 磁盘不足
