## 1. 定位

| 项 | 说明 |
|----|------|
| 目标 | 演示 **高并发秒杀**：Redis Lua 原子扣库存 + 异步落 MySQL |
| 场景 | k6 压测、架构学习、网关→order 全链路 |
| 非目标 | 支付、库存预占超时、分库分表、MQ 解耦（v1 用 Redis List 队列） |

## 3. 核心流程

### 3.1 下单（同步路径）

1. `SeckillController.order` 校验 `activityId`、`userId`
2. `SeckillService.placeOrder` 执行 **Lua 脚本**（单 Redis 原子）：
   - 检查库存 `stockKey`
   - 检查用户是否已购 `userKey`（防重复）
   - 扣减库存；记录用户；**RPUSH** 订单 JSON 到 `queueKey`
   - 更新 `metricsKey` 计数
3. 返回 `SeckillOrderResult`：`SUCCESS` / `SOLD_OUT` / `DUPLICATE` / …

### 3.2 落库（异步路径）

- `SeckillOrderConsumer` 定时 `drainQueues`（默认 50ms）
- 从 `queueKey` **LPOP** 批量取订单 → `seckill_order` INSERT
- 配置：`moli.seckill.async-db=true`（默认开启）

### 3.3 活动初始化

- DB 种子：`docs/sql/02_seckill_schema.sql` → `seckill_activity` id=1，stock=1_000_000
- 压测模式：`POST /seckill/admin/init`（仅 `loadtest` profile）

## 4. 数据模型

### 4.1 MySQL（`docs/sql/02_seckill_schema.sql`）

| 表 | 说明 |
|----|------|
| `seckill_activity` | 活动 id、名称、初始库存、已售、状态 |
| `seckill_order` | 订单 id（雪花）、activity_id、user_id、request_id |

### 4.2 Redis Key（前缀 `moli.seckill.redis-key-prefix`，默认 `moli:seckill:`）

| Key 模式 | 用途 |
|----------|------|
| `{prefix}stock:{activityId}` | 剩余库存 |
| `{prefix}user:{activityId}` | 已购用户 Set |
| `{prefix}queue:{activityId}` | 待落库订单 List |
| `{prefix}metrics` | 压测计数 Hash |

## 5. 关键类

| 类 | 职责 |
|----|------|
| `SeckillController` | HTTP `/seckill/*` |
| `SeckillService` | Lua 执行、活动查询、metrics |
| `SeckillLuaScripts` | 扣库存脚本 |
| `SeckillOrderConsumer` | 异步落库 |
| `SeckillProperties` | 前缀、loadtest 开关、batch 大小 |

## 6. 运行时

| 项 | 值 |
|----|----|
| HTTP 端口 | **8087** |
| Dubbo 端口 | **20882** |
| 网关 | `/OrderServer/**` → StripPrefix=1 |
| Redis | 与 user-center 同实例，**database=1** |
| Profile | `dev` 日常；`loadtest` 压测（开放 admin/init） |

---

## 7. 与鉴权

- `/seckill/ping`、`/seckill/metrics`：压测探测，**无 Shiro**
- `/seckill/order`：压测场景通常直连或网关，loadtest 下可配合 user-center `/loadtest/login` 拿 token（order 侧秒杀接口本身不强制登录，便于纯 RPS 压测）

---

## 8. 限制与后续

| 限制 | 说明 |
|------|------|
| Consumer 仅 drain activityId=1 | 压测默认活动；生产应 MQ 分片 |
| 无分布式事务 | 以 Redis 为准，DB 最终一致 |
| 无退款/关单 | v2+ |
