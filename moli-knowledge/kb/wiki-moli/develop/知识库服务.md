# 知识库服务（knowledge-server）

企业知识库的 **Java REST 后端**。注意它与 `kb/`（LLM-Wiki markdown 知识库）是**双轨**关系——分工约定见 `kb/ROADMAP.md` §〇。

| 项 | 值 |
|----|----|
| 服务名 | `knowledge-server` |
| HTTP 端口 | 8090 |
| Dubbo 端口 | 20884（Consumer） |
| 网关路由 | `/KnowledgeServer/**` → StripPrefix=1 |

## 能力（六大域 CRUD）

| 域 | 路径前缀 | 能力 |
|----|----------|------|
| 空间 | `/kb/space` | 分页/详情/增删改，编码唯一，可见性 |
| 分类 | `/kb/category` | 树形查询/增删改 |
| 文档 | `/kb/document` | 搜索/详情/保存/发布/归档/删/版本 |
| 标签 | `/kb/tag` | 列表/增删改 |
| 评论 | `/kb/comment` | 分页/增/删（支持 parentId） |
| 收藏 | `/kb/favorite` | 添加/取消/我的 |

表：`kb_space/category/document/tag/document_tag/comment/document_version/favorite/attachment`（`docs/sql/03_knowledge_schema.sql`）。

## 浏览 / 问答 / 管理 API

| 能力 | 路径 | 说明 |
|------|------|------|
| 目录 meta | `GET /kb/index?groupBy=category` | 按**分类**分组计数（仅支持 `category`，`type` 等 400 拒绝） |
| 分组条目 | `GET /kb/index/items` | 展开分组时分页拉 slug/title |
| 目录搜索 | `GET /kb/index/search` | 浏览侧栏服务端过滤 |
| slug 定位 | `GET /kb/index/locate` | 深链展开所属分组 |
| **体裁 facet** | `GET /kb/index/types` | 体裁筛选行 chip 计数（进页不传 categoryId；见 §2.1.3） |
| **体裁白名单** | `GET /kb/meta/kb-types` | 体裁下拉数据源 |
| 文档搜索 | `GET /kb/document/search` | `kbType` + `categoryId` **平行 AND** 过滤 |
| 单页 | `GET /kb/page?slug=` | Markdown + 出/入链 |
| 问答 | `POST /kb/ask` | LLM 或检索式 |
| 图谱 | `GET /kb/graph` | 关系可视化（边读 kb_relation；大库度数裁剪 + meta） |
| 图谱邻域 | `GET /kb/graph/ego` | 以某文档为中心 BFS 子图 |
| 体检 | `GET /kb/lint` | 断链/孤儿 |
| CRUD | `/kb/space` `/kb/document` … | 空间/文档管理 |

**体裁 × 分类 = 平行双 facet**（两行 chip，默认均可「全部」；列表 `search` AND 查询）。勿再做「先选分类再出体裁」嵌套。enterprise-kb 分类名与体裁名可能重合，见 API §2.1.3。维护仍走 frontmatter `type:` → Sync。

操作见 [[知识库使用指南]]；**API 详情见 `docs/api/KNOWLEDGE_API.md` §2.1.1–§2.1.3 与 search 参数表**。

## 现状（实事求是）

- **检索**走 MySQL **ngram 全文索引** `ftx_kb_document(title,summary,content)`（`MATCH ... AGAINST`，`kb.search.mode=fulltext`，`like` 为兼容回退）；`/kb/ask` 先用全文按相关度召回 top-N（`kb.search.ask-candidate-limit`）再内存 bigram 精排，避免全量扫描；可配 LLM（DeepSeek 等）。文档量/召回信号触发再升级 Meilisearch/ES，接入蓝图见 [[知识库-meilisearch接入规划]]。
- **空间级 ACL** 已实现（visibility 元数据 + 成员角色；平台超管 bypass），见 [[知识库使用指南]] §5。
- **附件**：MinIO + `kb_attachment`，见 [[minio-附件存储指南]]。
- 已在 `sys_system` 注册（id=39，`moli-knowledge`，EXTERNAL SSO），见 [[sso与系统门户]]。

## 与 kb/ 的关系

按 `kb/ROADMAP.md` §〇：**知识在 `kb/`（markdown）里产生，本服务作 Sync 只读门面**。M2 ✅：`sync_to_db.py` + `slug` 唯一键 + 浏览/问答 API；M5–M7 工作台见 ROADMAP。  
为何这样设计、与 Confluence / Docusaurus 等业界方案对比，见 [[知识库设计哲学-docs-as-code]]。
