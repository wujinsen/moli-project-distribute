# 秒杀全链路与压测要点汇总

> **Query crystallize 页**：综合 [[秒杀设计]]、[[秒杀压测指南]]、压测/监控/限流/MQ 相关页，供压测前 checklist 与排障。细节以源页为准。

## 1. 全链路（一图）

```mermaid
flowchart LR
  k6[秒杀压测指南 / wrk] --> GW[Gateway 21000]
  GW --> Order[order-server /seckill]
  Order --> Lua[Redis Lua 扣库存]
  Lua --> Q[Redis List 队列]
  Q --> Consumer[@Scheduled Consumer]
  Consumer --> MySQL[(seckill_order)]
  Order -.->|鉴权| RedisSession[Redis Shiro Session]
  Order -.->|可选| UC[Dubbo user-center]
```

| 阶段 | 技术 | 瓶颈常见点 |
|------|------|------------|
| 入口 | Gateway → Order | **无限流** `moli-knowledge/kb/wiki/middleware/sentinel-限流与熔断.md` |
| 热路径 | Redis + Lua | Redis 未起、库存未预热 |
| 鉴权 | Shiro + Redis | Redis database 不一致 [[茉莉登录与鉴权故障根因汇总]] |
| 异步落库 | List + 定时轮询 | 非 MQ，堆积在 Redis |
| 持久化 | MyBatis + Druid | 池满、慢 SQL [[茉莉-druid-监控]] |

## 2. 压测前 checklist

-  Nacos + MySQL + Redis 已启动 [[项目文档总览]]
-  `init-db.ps1` + `02_seckill_schema.sql` + 秒杀数据脚本 [[秒杀压测指南]]
-  user-center → order → gateway 启动顺序
-  loadtest profile：`/UserCenter/loadtest/login` [[茉莉-loadtest-账号]]
-  Redis 库存/活动预热（`load-test/scripts/init-seckill-data.*`）
-  各服务 Redis **database 一致**
-  Grafana/Prometheus 可选 [[茉莉-prometheus-大盘]]

## 3. 关键 API

| 接口 | 说明 |
|------|------|
| `POST .../OrderServer/seckill/order` | 热路径，Lua 原子扣减 |
| `GET .../seckill/activity/{id}` | 活动查询 |
| loadtest login | 免菜单，适合 秒杀压测指南 |

经网关前缀 `/OrderServer/`，StripPrefix=1。

## 4. 响应语义（压测断言）

| HTTP/业务 | 含义 |
|-----------|------|
| 200 OK | 抢购成功（进队列） |
| 409 / SOLD_OUT | 库存耗尽（预期部分比例） |
| 429 / DUPLICATE | 重复抢购 |
| 401 / 10006 | **鉴权/Redis**，非秒杀逻辑 [[茉莉登录与鉴权故障根因汇总]] |

秒杀压测指南 脚本见 `load-test/k6/seckill-*.js`。

## 5. 监控看什么

| 指标 | 解读 |
|------|------|
| Redis CPU/ops | Lua 热点 |
| `druid.pool.waiting` | 落库跟不上 [[茉莉-druid-监控]] |
| JVM GC | Consumer 批量 insert 压力 |
| Gateway 502 | 下游未注册/未启动 |

## 6. 已知架构限制（压测解读用）

来自 [[秒杀设计]]：

- 异步为 **Redis 队列 + @Scheduled**，非 MQ
- Consumer 压测模式硬编码 `activityId=1`
- 无 Sentinel 网关限流
- 无支付/回滚/死信

压测 QPS 高但 **MySQL 行数少于成功数** → 查 Consumer 与队列积压。
