# 服务调用与架构

茉莉是一套 Spring Cloud Alibaba 分布式微服务，核心是**权限管理系统**。

## 全链路

```
浏览器 → moli-gateway:21000 (路由转发, 无鉴权)
            ├ /UserCenter/**    → user-center-server:8888  (权限中枢)
            ├ /OrderServer/**   → order-server:8087
            ├ /BiServer/**      → bi-server:1128
            └ /KnowledgeServer/** → knowledge-server:8090
                       │
   业务服务 ──Dubbo(version=1.0.0,group=moli)──▶ user-center 拉权限/校验
   全服务 ──共享同一 Redis──▶ Shiro Session
```

## 调用分层（决策）

| 场景 | 方式 |
|------|------|
| 外部 → 系统 | HTTP/REST，统一经 [[网关]] |
| 服务 → 服务 | **Spring Cloud Dubbo RPC**（已移除 OpenFeign） |
| 鉴权契约 | Dubbo 接口 `UserCenterServer`（getInfoByUserName / getUserById / getPermissionsByUserId） |

## 基础设施

| 能力 | 组件 |
|------|------|
| 服务发现 | Nacos Discovery（`:8848`，命名空间 dev） |
| 配置中心 | Nacos Config（**当前各服务多为注释/未启用**） |
| 网关 | Spring Cloud Gateway + Ribbon `lb://` |
| RPC | Dubbo（端口 20881~20884） |
| 会话/缓存 | Redis（共享） |
| 持久化 | MySQL + MyBatis-Plus + Druid |

## 鉴权边界（五层，理想模型）

网关（建议加 Sentinel）→ Shiro `authc` → 账号状态校验 → `@RequiresPermissions` → Dubbo 内网调用。
现状：网关**未做鉴权也未接 Sentinel**，鉴权实际落在各服务 Shiro，见 [[认证与会话机制]]。

## 启动顺序

Nacos → Redis → MySQL → user-center → order/bi/knowledge → gateway → 前端。详见 [[本地启动指南]]。
