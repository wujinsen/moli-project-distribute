# 可观测性 · 生产部署与日志可靠性

> 工程契约：`docs/ops/observability-production.md`  
> PoC 本地栈见 [[可观测性平台]] · 日常 LogQL 见 [[监控与日志]]

## 1. 核心原则

**Grafana 能查到 ≠ 日志唯一来源。** 生产靠 **本地 log 文件是真相源，Loki 是查询加速层**。

| 原则 | 说明 |
|------|------|
| 本地落盘必须 | Logback → `logs/{service}.log`；监控全挂仍写盘 |
| 采集解耦 | Alloy / SW Agent 独立进程，不阻塞 JVM |
| 监控机分离 | 业务机 Alloy；监控机 Loki/Prometheus/Grafana |
| Loki 对象存储 | PoC filesystem 卷不够；生产 S3/MinIO/COS |
| 栈故障不影响业务 | Loki/Grafana down → 请求仍成功 |

## 2. 部署拓扑

架构图（draw.io）：`docs/diagrams/moli-observability-prod-topology.drawio`  
导出 PNG：`docs/diagrams/png/moli-observability-prod-topology.png`

### 业务主机

- Java：`/opt/moli-project-distribute/`，systemd + `moli-service.sh`
- 日志：`moli-*/logs/{service}.log`，MyBatis `Slf4jImpl`
- **Alloy**：systemd 托管，`Restart=always`
- SkyWalking Agent：可选，`SKYWALKING_ENABLED=true`
- Actuator：**仅管理网**，不经 Gateway

### 监控主机

- Prometheus、Loki（+ **对象存储**）、Grafana、SkyWalking OAP/UI
- 内网访问；Grafana 改默认密码

## 3. 日志四层可靠性

图：`docs/diagrams/moli-observability-log-resilience.drawio`

| 层 | 组件 | 挂了怎么办 |
|----|------|------------|
| **L1** | 本地 log 文件 | 运维 SSH `tail/grep`；**最后一道保险** |
| **L2** | Alloy | 远程暂停；恢复后 offset 补采 |
| **L3** | Loki + 对象存储 | Grafana 查不到；本地 log 仍在 |
| **L4** | OSS 冷归档（可选） | 合规 90d+；Loki retention 外历史 |

## 4. 常见操作 vs 丢数

| 操作 | 本地 log | Loki 数据 |
|------|----------|-----------|
| `compose stop` | ✅ | ✅ 卷保留 |
| `compose down`（无 `-v`） | ✅ | ✅ |
| `compose down -v` | ✅ | ❌ **丢失** |
| Alloy 停机 | ✅ 仍写 | 暂停 ingest |
| 磁盘满 | ❌ **风险** | — |

**生产禁止 `docker compose down -v`。**

## 5. 发布检查

对照 [[生产环境检查清单]] §6，并确认：

1. Alloy systemd 运行
2. Loki 已接对象存储（非仅 container 盘）
3. 磁盘 / ingest 失败告警
4. 演练：停 Loki 10min → 业务正常 → 恢复后补采

## 6. Alloy systemd（摘要）

```ini
# /etc/systemd/system/moli-alloy.service
[Service]
ExecStart=/usr/local/bin/alloy run \
  --storage.path=/var/lib/moli-alloy \
  /opt/moli-project-distribute/deploy/observability/alloy/config.prod.alloy
Restart=always
```

生产须改：Loki push URL（监控机内网）、tail 路径、`env=prod` 标签。完整模板见 `docs/ops/observability-production.md` §6。
