# 监控与日志 · v1 运维要点

> 完整 APM 规划见 `docs/zh-CN/TECH_STACK.md`  
> **与排障配合**：监控/告警先看本页；定位根因与动作表见 [[故障排查指南]]（「监控告警 + 故障排查」联读）。

## 0. 监控告警怎么和故障排查一起看

| 步骤 | 看哪页 | 做什么 |
|------|--------|--------|
| 1 | **本页（监控与日志）** | 确认告警/健康探测/日志是否刷 ERROR、哪个服务 |
| 2 | [[故障排查指南]] | 按现象进决策树（登录 500、401、No provider、CORS…） |
| 3 | 仍不清 | [[茉莉登录与鉴权故障根因汇总]] 或服务专项 Runbook |

一句话：**告警/日志异常 → 先本页收窄服务与信号 → 再 [[故障排查指南]] 对症处理**。

## 1. 日志

各服务 `logback-spring.xml` — 发版后 15 分钟内 **无 ERROR 持续刷屏**。

| 服务 | 关注 |
|------|------|
| user-center | 登录、Shiro、Dubbo |
| gateway | 503、路由超时 |
| order | 秒杀、Redis |
| knowledge | Ingest、Sync、LLM |

## 2. 健康探测

| 探测 | URL |
|------|-----|
| 网关 | `/OrderServer/seckill/ping` |
| 登录 | `POST /UserCenter/login` |
| 知识库 | `/KnowledgeServer/kb/index` |

见 [[测试文档索引]] 冒烟清单。

## 3. 知识库专项

- Sync 失败 → `kb_sync_log`、应用日志
- Lint CI → `python kb/tools/lint.py --strict`
- Web 页旧 → 是否 `sync-all`

## 4. 基础设施（建议）

MySQL 连接数 · Redis 内存 · Nacos 心跳 · 磁盘

工程原文：`docs/ops/monitoring-and-logs.md`
