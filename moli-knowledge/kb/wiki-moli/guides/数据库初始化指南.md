# 数据库初始化指南



> 启动顺序见 [[本地启动指南]]；压测表与 k6 见 [[秒杀压测指南]]；知识库表与 sync 见 [[wiki同步指南]]。



面向「新环境 / 本机第一次」如何把 **MySQL `moli` 库** 建全。



## 0. 字符集约束（utf8mb4 · 必读）



| 层级 | 要求 |

|------|------|

| 建库 | `DEFAULT CHARSET utf8mb4` |

| 表 | 见 `docs/sql/03_knowledge_schema.sql`，均为 utf8mb4 |

| **mysql 客户端** | 导入含中文的 SQL 时必须 **`--default-character-set=utf8mb4`** |

| 脚本文件 | 含中文的种子在文件头写 **`SET NAMES utf8mb4;`** |



**禁止**在 PowerShell 里用 `Get-Content ... | mysql` 管道导入**含中文**的 SQL——即使 `-Encoding UTF8`，客户端连接仍可能按 latin1 写入，表现为 Navicat 里 `space_name`/`description` 全是 `?`。



**推荐**：



- 一键：`.\scripts\init-db.ps1`（内部 `source` + utf8mb4）

- 单文件：



```powershell

& "C:\Program Files\MySQL\MySQL Server 8.0\bin\mysql.exe" -u root -p12345678 --default-character-set=utf8mb4 moli -e "source D:/work/moli_project/moli-project-distribute/docs/sql/07_kb_space_ops_manual.sql"

```



详细说明见 `docs/sql/README.md`、`scripts/README.md`。



## 1. 权威数据源



| 文件 | 用途 |

|------|------|

| **`scripts/moli.sql`** | **全库快照**（结构 + 种子数据：用户/角色/菜单等） |

| `docs/sql/02_seckill_schema.sql` | 秒杀表（压测用，全库不含时追加） |

| `docs/sql/03_knowledge_schema.sql` | 知识库表 `kb_*`（[[知识库服务]] 用） |

| `docs/sql/04_knowledge_menu.sql` | 知识库菜单 |

| `docs/sql/07_kb_space_ops_manual.sql` | 茉莉系统手册独立空间（含中文，**须 utf8mb4 导入**） |



早期 `docs/sql/00_schema.sql`、`01_baseline_data.sql` 已废弃，**以 `scripts/moli.sql` 为准**。



## 2. Windows 一键导入（推荐）



```powershell

cd D:\work\moli_project\moli-project-distribute

.\scripts\init-db.ps1

```



可选开关：



| 参数 | 效果 |

|------|------|

| `-SkipSeckill` | 不导入秒杀表 |

| `-SkipKnowledge` | 不导入知识库表 |

| `-Password xxx` | 覆盖默认 root 密码 |



脚本顺序：建库 → `moli.sql` → 秒杀 → 知识库表/菜单/茉莉系统手册空间 → 打印前 5 个用户。全程 **`--default-character-set=utf8mb4` + `source`**，见 §0。



## 3. 手动导入（CMD）



```cmd

"C:\Program Files\MySQL\MySQL Server 8.0\bin\mysql.exe" -u root -p12345678 --default-character-set=utf8mb4 -e "CREATE DATABASE IF NOT EXISTS moli DEFAULT CHARSET utf8mb4;"

"C:\Program Files\MySQL\MySQL Server 8.0\bin\mysql.exe" -u root -p12345678 --default-character-set=utf8mb4 moli < scripts\moli.sql

"C:\Program Files\MySQL\MySQL Server 8.0\bin\mysql.exe" -u root -p12345678 --default-character-set=utf8mb4 moli < docs\sql\02_seckill_schema.sql

"C:\Program Files\MySQL\MySQL Server 8.0\bin\mysql.exe" -u root -p12345678 --default-character-set=utf8mb4 moli < docs\sql\03_knowledge_schema.sql

```



Navicat：选中 `moli` → **连接字符集 utf8mb4** → 运行 SQL 文件 → 同上顺序。



## 4. 演示账号与密码



`moli.sql` 含 `zhangsan`、`admin`、`superadmin` 等，**默认密码均为 `123456`**：



- 存储：**SHA-256 + salt `moli`，15 轮**

- `password` 列为 **64 位哈希**，不是明文



若 Navicat 里哈希差一个字符或仍是旧值，登录会失败。一键重置所有演示用户：



```powershell

& "C:\Program Files\MySQL\MySQL Server 8.0\bin\mysql.exe" -u root -p12345678 --default-character-set=utf8mb4 moli -e "source D:/work/moli_project/moli-project-distribute/scripts/reset-demo-passwords.sql"

```



登录流程见 [[登录与鉴权指南]]。



## 5. 与各服务的连接



各模块 `application-dev.yml` 典型配置：



```yaml

spring:

  datasource:

    url: jdbc:mysql://127.0.0.1:3306/moli?...

    username: root

    password: 12345678

```



改密码后需**所有服务**对齐。连接池问题见 [[故障排查指南]]。

## 7. 常见问题



| 现象 | 处理 |

|------|------|

| **`kb_space` 中文变 `?`** | 用错误方式（PowerShell 管道）导入了含中文种子；执行 `07_kb_space_ops_manual_fix_charset.sql` 或按 §0 重导 |

| 导入报字符集错误 | 库 `utf8mb4`；客户端 `--default-character-set=utf8mb4`；禁止含中文 SQL 用 `Get-Content \| mysql` |

| 登录 500 但 DB 正常 | 多为 **Redis 未启动**，见 [[故障排查指南]] |

| 表已存在冲突 | 新环境 drop 库重建；生产勿直接覆盖 |

| 缺少 kb_ 表 | 补跑 `03_knowledge_schema.sql` |
