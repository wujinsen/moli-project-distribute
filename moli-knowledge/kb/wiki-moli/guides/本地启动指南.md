# 本地启动指南

面向「我想在本机把茉莉微服务跑起来」的操作指导。

## 1. 环境要求

| 依赖 | 版本建议 |
|------|----------|
| JDK | 1.8 |
| Maven | 3.6+ |
| Nacos Server | 2.0.3 |
| MySQL | 8.0.3 |
| Redis | 5.0.13 |

## 2. 先启动基础设施

1. 启动 **Nacos**（本地 Docker 默认 `http://127.0.0.1:28548`，账号/密码 `nacos/nacos`，命名空间 `dev`）。Windows 裸进程也可用 `8848`，与各服务 `bootstrap.yml` 一致即可。
2. 启动 **MySQL**，建库 `moli`，导入脚本 — 详见 [[数据库初始化指南]]（`scripts/moli.sql` + 秒杀 + 知识库表）。
3. 启动 **Redis**（本地 Windows 默认 **`16379`**；Linux 生产常用 `6379`）——全服务共享，用于 Shiro 分布式 Session，详见 [[认证与会话机制]]。

> **Windows 说明**：Hyper-V/WSL 可能预留 `6318–6417` 端口段，标准 `6379` 无法绑定。请在本机 `redis.windows.conf` 设置 `port 16379`，与各服务 `application-dev.yml` 保持一致。

> **本地部署拓扑**：`docs/diagrams/png/moli-deploy-topology.png`（请在 IDE 中打开仓库文件查看）

> 可编辑源文件：`docs/diagrams/moli-deploy-topology.drawio`

> ⚠️ 关键：order / bi / knowledge 与 user-center **必须连同一个 Redis（host/port/password/database 都要一致）**，否则跨服务会话校验失败。

## 3. 修改配置

- Nacos 地址与命名空间：各服务 `bootstrap.yml`
- 数据库 / Redis 连接：各模块 `application-dev.yml`

## 4. 编译

```bash
# 1) 安装父 POM（版本管理）
cd moli-distribute-parent && mvn clean install -DskipTests
# 2) 安装公共模块
cd ../moli-distribute-common && mvn clean install -DskipTests
# 3) 按需编译业务模块
cd ../moli-user-center && mvn clean package -DskipTests
```

## 5. 启动顺序（重要）

按依赖关系依次启动（推荐 IDEA `.run/* (dev).run.xml`，工作目录 `$PROJECT_DIR$`）：

1. [[用户中心]]（`user-center-server`，HTTP **28101**）—— 权限中枢，其它服务依赖它鉴权
2. [[订单服务]]（`order-server`，HTTP **28102**）—— 通过 Dubbo 调用用户中心
3. [[bi服务]] / [[AI模块-概要设计]]（`ai-server`，HTTP **28103**，可选）
4. [[知识库服务]]（`knowledge-server`，HTTP **28104**，可选）
5. [[网关]]（`moli-gateway`，HTTP **28100**）—— 对外统一入口（开发联调可直连各服务端口）

启动后经网关访问（网关按前缀转发并 StripPrefix=1）：

```
http://localhost:28100/UserCenter/...
http://localhost:28100/OrderServer/...
http://localhost:28100/KnowledgeServer/...
```

## 6. 可观测性栈（可选）

本地查指标/日志/链路时，另起 Docker 栈：

```powershell
docker compose -f deploy/observability/docker-compose.observability.yml up -d
```

| 组件 | 地址 |
|------|------|
| Grafana | http://127.0.0.1:28300 |
| Prometheus | http://127.0.0.1:29090 |
| Loki | http://127.0.0.1:28110 |

日志采集依赖各 Java 服务 **log 文件落盘**（非 IDEA 控制台）。详见 [[监控与日志]] · [[可观测性平台]]。

## 常见问题定位

- 服务注册不上 → 确认 Nacos 已启动（Docker **28548** 或裸进程 **8848**）、`bootstrap.yml` 命名空间为 `dev`。
- 登录态/权限异常 → 见 [[认证与会话机制]]，确认各服务 Redis 连接（含 database）一致。
- 怎么登录、怎么带 token 调接口 → 见 [[登录与鉴权指南]]；Swagger 调试见 `guides/swagger接口调试指南`（延伸，不入图谱边）。
- **系统性的报错排查** → 见 [[故障排查指南]]（Redis 未启动、Dubbo No provider 等）。
- 前端联调、跨域 → 见 `guides/前端开发与联调指南`；容器化依赖 → `ops/docker部署指南`（延伸，不入图谱边）。
- **Grafana 查不到日志** → 见 [[监控与日志]] §3；确认 log 文件在模块 `logs/` 下更新、MyBatis 为 `Slf4jImpl`。
- **新人 Day-1** → [[茉莉新人上手checklist]]。

> 📌 端口以 `docs/ops/local-dev-ports.md` 与代码 `application-dev.yml` 为准（281xx 段）。旧文档中的 8888 / 21000 / 8848 已过时。
