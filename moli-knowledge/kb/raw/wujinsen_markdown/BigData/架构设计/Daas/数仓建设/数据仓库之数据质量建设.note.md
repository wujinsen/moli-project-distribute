数仓建设真正的难点不在于数仓设计，⽽在于后续业务发展起来，业务线变的庞⼤之后的数据治理， ⽽数据治理的范围⾮常⼴，包含数据本&#12189;的管理、数据安全、数据质量、数据成本等。在这么 多治理内容中，⼤家想下最重要的治理是什么？当然是数据质量治理，因为数据质量是数据分析结论 有效性和准确性的基础，也是这⼀切的前提。所以如何保障数据质量，确保数据可⽤性是数据仓库建 设中不容忽视的环节。

数据质量涉及的范围也很⼴，贯穿数仓的整个⽣命周期，从数据产⽣->数据接⼊->数据存储->数据处 理->数据输出->数据展示，每个阶段都需要质量治理。

在系统建设的各个阶段都应该根据标准进⾏数据质量检测和规范，及时进⾏治理，避免事后的清洗⼯ 作。

# 1. 为什么要进⾏数据质量评估

很多刚⼊⻔的数据⼈，拿到数据后会⽴刻开始对数据进⾏各种探查、统计分析等，企图能⽴即发现数 据背后隐藏的信息和知识。然⽽忙活了⼀阵才颓然发现，并不能提炼出太多有价值的信息，⽩⽩浪费 了⼤量的时间和精⼒。⽐如和数据打交道的过程中，可能会出现以下的场景：

场景⼀：作为数据分析⼈员，要统计⼀下近 7 天⽤户的购买情况，结果从数仓中统计完发现，很多数 据发⽣了重复记录，甚⾄有些数据统计单位不统⼀。

场景⼆：业务看报表，发现某⼀天的成交 gmv 暴跌，经过排查发现，是当天的数据缺失。

造成这⼀情况的⼀个重要因素就是忽视了对数据质量的客观评估，没有制定合理的衡量标准，导致没 有发现数据已出现问题。所以，进⾏科学、客观的数据质量衡量标准是⾮常必要且⼗分重要的。

# 2. 数据质量衡量标准

如何评估数据质量的好坏，业界有不同的标准，我总结了以下六个维度进⾏评估，包括完整性、规范 性、⼀致性、准确性、唯⼀性、及时性。

数据完整性

完整性指的是数据信息是否存在缺失的状况，数据缺失的情况可能是整个数据记录缺失，也可能是数 据中某个字段信息的记录缺失。

数据规范性

规范性指的是描述数据遵循预定的语法规则的程度，是否符合其定义，⽐如数据的类型、格式、取值 范围等。

数据⼀致性

⼀致性是指数据是否遵循了统⼀的规范，数据集合是否保持了统⼀的格式。数据质量的⼀致性主要体 现在数据记录的规范和数据是否符合逻辑，⼀致性并不意味着数值上的绝对相同，⽽是数据收集、处 理的⽅法和标准的⼀致。常⻅的⼀致性指标有：ID 重合度、属性⼀致、取值⼀致、采集⽅法⼀致、转 化步骤⼀致。

数据准确性

准确性是指数据记录的信息是否存在异常或错误。和⼀致性不⼀样，存在准确性问题的数据不仅仅只 是规则上的不⼀致，更为常⻅的数据准确性错误就如乱码，其次异常的⼤或者⼩的数据也是不符合条 件的数据。常⻅的准确性指标有：缺失值占⽐、错误值占⽐、异常值占⽐、抽样偏差、数据噪声。

数据唯⼀性

唯⼀性指的是数据库的数据不存在重复的情形。⽐如真实成交 1 万条，但数据表有 3 0 条重复了， 成了 1.3 万条成交记录，这种数据不符合数据唯⼀性。

数据及时性

及时性是指数据从产⽣到可以查看的时间间隔，也叫数据的延时时⻓。⽐如⼀份数据是统计离线今⽇ 的，结果都是第⼆天甚⾄第三天才能统计完，这种数据不符合数据及时性。

# 1. 数据资产等级

- 1) 等级定义

根据当数据质量不满⾜完整性、规范性、⼀致性、准确性、唯⼀性、及时性时，对业务的影响程度⼤ ⼩来划分数据的资产等级。

毁灭性：数据⼀旦出错，会引起巨⼤的资产损失，⾯临重⼤收益受损等。标记为 L1 全局性：数据⽤于集团业务、企业级效果评估和重要决策任务等。标记为 L2 局部性：数据⽤于某个业务线的⽇常运营、分析报告等，如果出现问题会给该业务线造成⼀定的影

响或影响其⼯作效率。标记为 L3 ⼀般性：数据⽤于⽇常数据分析，出现问题的带来的影响很⼩。标记为 L4 未知性质：⽆法追溯数据的应⽤场景。标记为 Lx

重要程度：L1>L2>L3>L4>Lx。如果⼀份数据出现在多个应⽤场景中，则根据其最重要程度进⾏标 记。

- 2) 等级划分


定义数据资产等级后，我们可以从数据流程链路开始进⾏数据资产等级标记，完成数据资产等级确 认，给不同的数据定义不同的重要程度。

# 2. 数据加⼯过程卡点校验

- 1) 在线系统数据校验


在线业务复杂多变，总是在不断地变更，每⼀次变更都会带来数据的变化，数据仓库需要适应这多变 的业务发展，及时做到数据的准确性。

基于此，在线业务的变更如何⾼效地通知到离线数据仓库，同样也是需要考虑的问题。为了保障在线 数据和离线数据的⼀致性，我们可以通过⼯具+⼈员管理并⾏的⽅式来尽可能的解决以上问题：既要在 ⼯具上⾃动捕捉每⼀次业务的变化，同时也要求开发⼈员在意识上⾃动进⾏业务变更通知。

# 1、业务上线发布平台：

监控业务上线发布平台上的重⼤业务变更，通过订阅这个发布过程，及时将变更内容通知到数据部 ⻔。

由于业务系统复杂多变，若⽇常发布变更频繁，那么每次都通知数据部⻔，会造成不必要的资源浪 费。这时，我们可以使⽤之前已经完成标记的数据资产等级标签，针对涉及⾼等级数据应⽤的数据资 产，整理出哪些类型的业务变更会影响数据的加⼯或者影响数据统计⼝径的调整，则这些情况都必须 及时通知到数据部⻔。

如果公司没有⾃⼰的业务发布平台，那么就需要与业务部⻔约定好，针对⾼等级的数据资产的业务变 更，需要以邮件或者其他书⾯的说明及时反馈到数据部⻔。

# 2、操作⼈员管理：

⼯具只是辅助监管的⼀种⼿段，⽽使⽤⼯具的⼈员才是核⼼。数据资产等级的上下游打通过程需要通 知给在线业务系统开发⼈员，使其知道哪些是重要的核⼼数据资产，哪些暂时还只是作为内部分析数 据使⽤，提⾼在线开发⼈员的数据⻛险意识。

可以通过培训的⽅式，把数据质量管理的诉求，数据质量管理的整个数据加⼯过程，以及数据产品的 应⽤⽅式及应⽤场景告知在线开发⼈员，使其了解数据的重要性、价值及⻛险。确保在线开发⼈员在 完成业务⽬标的同时，也要考虑数据的⽬标，保持业务端和数据段⼀致。

- 2) 离线系统数据校验


数据从在线业务系统到数据仓库再到数据产品的过程中，需要在数据仓库这⼀层完成数据的清洗、加 ⼯。正是有了数据的加⼯，才有了数据仓库模型和数据仓库代码的建设。如何保障数据加过程中的质 量，是离线数据仓库保障数据质量的⼀个重要环节。

在这些环节中，我们可以采⽤以下⽅式来保障数据质量：

代码提交核查：

开发相关的规则引擎，辅助代码提交校验。规则分类⼤致为：

代码规范类规则：如表命名规范、字段命名规范、⽣命周期设置、表注释等；

代码质量类规则：如分⺟为 0 提醒、NUl 值参与计算提醒等；

代码性能类规则：如⼤表提醒、重复计算监测、⼤⼩表 join 操作提醒等。

代码发布核查：

加强测试环节，测试环境测试后再发布到⽣成环境，且⽣成环境测试通过后才算发布成功。

任务变更或重跑数据：

在进⾏数据更新操作前，需要通知下游数据变更原因、变更逻辑、变更时间等信息。下游没有异议 后，再按照约定时间执⾏变更发布操作。

# 3. 数据处理⻛险监控

⻛险点监控主要是针对数据在⽇常运⾏过程中容易出现的⻛险进⾏监控并设置报警机制，主要包括在 线数据和离线数据运⾏⻛险点监控。

- 1) 数据质量监控


在线业务系统的数据⽣产过程需要保证数据质量，主要根据业务规则对数据进⾏监控。

⽐如交易系统配置的⼀些监控规则，如订单拍下时间、订单完结时间、订单⽀付⾦额、订单状态流转 等都配置了校验规则。订单拍下时间肯定不会⼤于当天时间，也不会⼩于业务上线时间，⼀旦出现异 常的订单创建时间，就会⽴刻报警，同时报警给到多⼈。通过这种机制，可以及时发现并解决问题。

随着业务负责程度的提升，会导致规则繁多、规则配置的运⾏成本增⼤，这时可以按照我们之前的数 据资产等级有针对性的进⾏监控。

离线数据⻛险点监控主要包括对数据准确性和数据产出及时性的监控。对数据调度平台上所有数据处 理调度进⾏监控。

我们以阿⾥的 DataWorks 数据调度⼯具为例，DataWorks 是基于 MaxCompute 计算引擎的⼀站式开 发⼯场，帮助企业快速完成数据集成、开发、治理、质量、安全等全套数据研发⼯作。

DataWorks 中的 DQC 通过配置数据质量校验规则，实现离线数据处理中的数据质量监控报警机制。

DQC 数据监控规则有强规则和弱规则：

强规则：⼀旦触发报警就会阻断任务的执⾏（将任务置为失败状态，使下游任务不会被触发执 ⾏）。

弱规则：只报警但不阻断任务的执⾏。

DQC 提供常⽤的规则模板，包括表⾏数较 N 天前波动率、表空间⼤⼩较 N 天前波动率、字段最⼤/最 ⼩/平均值相⽐ N 天前波动率、字段空值/唯⼀个数等。

DQC 检查其实也是运⾏ SQL 任务，只是这个任务是嵌套在主任务中的，⼀旦检查点太多⾃然就会影响 整体的性能，因此还是依赖数据产等级来确定规则的配置情况。⽐如 L1、L2 类数据监控率要达到 90% 以上，规则类型需要三种及以上，⽽不重要的数据资产则不强制要求。

- 2) 数据及时性监控


在确保数据准确性的前提下，需要进⼀步让数据能够及时地提供服务，否则数据的价值将⼤幅度降 低，甚⾄没有价值，所以确保数据及时性也是保障数据质量重中之重的⼀环。

任务优先级：

对于DataWorks平台的调度任务，可以通过智能监控⼯具进⾏优先级设置。DataWorks的调度是⼀个树 形结构，当配置了叶⼦节点的优先级，这个优先级会传递到所有的上游节点，⽽叶⼦节点通常就是服 务业务的消费节点。

因此，在优先级的设置上，要先确定业务的资产等级，等级越⾼的业务对应的消费节点优先级越⾼， 优先调度并占⽤计算资源，确保⾼等级业务的准时产出。

总之，就是按照数据资产等级优先执⾏⾼等级数据资产的调度任务，优先保障⾼等级业务的数据需 求。

任务报警：

任务报警和优先级类似，通过DataWorks的智能监控⼯具进⾏配置，只需要配置叶⼦节点即可向上游 传递报警配置。任务执⾏过程中，可能出错或延迟，为了保障最重要数据（即资产等级⾼的数据）产 出，需要⽴即处理出错并介⼊处理延迟。

DataWorks智能监控：

DataWorks进⾏离线任务调度时，提供智能监控⼯具，对调度任务进⾏监控告警。根据监控规则和任 务运⾏情况，智能监控决策是否报警、何时报警、如何报警以及给谁报警。智能监控会⾃动选择最合 理的报警时间、报警⽅式以及报警对象。

# 4. 最后

要想真正解决数据质量问题，就要明确业务需求并从需求开始控制数据质量，并建⽴数据质量管理机 制。从业务出发做问题定义，由⼯具⾃动、及时发现问题，明确问题责任⼈，通过邮件、短信等⽅式 进⾏通知，保证问题及时通知到责任⼈。跟踪问题整改进度，保证数据质量问题全过程的管理。
