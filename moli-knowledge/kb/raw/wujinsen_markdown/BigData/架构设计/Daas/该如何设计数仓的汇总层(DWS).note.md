ODS:操作型数据(Operational Data Store)，指结构与源系统基本保持⼀致的增量或者全量数据。作为 DW数据的⼀个数据准备区，同时⼜承担基础数据记录历史变化，之所以保留原始数据和线上原始 数据保持⼀致，⽅便后期数据核对需要。

CDM：通⽤数据模型，⼜称为数据中间层(Common Data Model)，包含DWD、DWS、DIM层。

DWD：数据仓库明细层数据(Data Warehouse Detail)。对ODS层数据进⾏清洗转化，以业务过程作为

建模驱动，基于每个具体的业务过程特点，构建最细粒度的明细事实表。可以结合企业的数据使⽤ 特点，基于维度建模思想，将明细事实表的某些重要属性字段做适当冗余，也即宽表化处理，构建 明细宽表。

DWS：数据仓库汇总层数据(Data Warehouse Summary)，基于指标需求，构建初步汇总事实表，⼀ 般是宽表。基于上层的应⽤和产品的指标需求，构建公共粒度的汇总指标表。以宽表化⼿段物理化 模型，构建命名规范、⼝径⼀致的统计指标，为上层提供公共指标。

DIM：建⽴⼀致数据分析维表，可以降低数据计算⼝径不统⼀的⻛险，同时可以⽅便进⾏交叉探 查。以维度作为建模驱动，基于每个维度的业务含义，通过添加维度属性、关联维度等定义计算逻 辑，完成属性定义的过程并建⽴⼀致的数据分析维表。

ADS：⾯向应⽤的数据服务层(Application Data Service)。整合汇总成分析某⼀个主题域的服务数

据，⾯向应⽤逻辑的数据加⼯。该层主要存放数据产品个性化的统计指标数据，这⼀层的数据直接 对接数据的消费者，是产品、运营等⻆⾊可以直接感知理解的⼀层，⼤多数这⼀层的表都可以直接 在BI上通过图表的形式直接透出。

对于复杂的业务场景⽽⾔，会出现很多跨域、跨事实的交叉探查，如果没有沉淀出DWS层的指标进 ⾏统⼀⼝径的收⼝，那么相同的指标会出现不同的⼝径和命名，其后果就是取数变得越来越不⽅ 便，⽽且容易造成业务怀疑数据是否正确的尴尬局⾯。

DWS层的设计原则

关于汇总层的表建模应遵循以下的原则：

数据公⽤性⽐如，汇总的聚集表能否与他⼈公⽤？基于某个维度的聚集是否是数据分析或者报表中 经常使⽤的？如果满⾜这些情况，我们就有必要把明细数据沉淀到汇总表中。

不跨数据域数据域是在较⾼层次上对数据进⾏分类聚集的抽象，如交易统⼀划到交易域下，商品的 新增、修改放到商品域下。

区分统计周期表命名上要能说明数据的统计周期，如_1d 表示最近1天，_td 截⽌到当天，_nd 表示最 近N天。

避免多个层级的数据应该避免将不同层级的数据放在⼀起，⽐如，如果存在7天和30天的事实，我们 可以选择⽤两列存放7天和30天的事实，但是需要在列名和字段注释上说明清楚。同时我们也可以使 ⽤两张表分别存储不同统计周期的数据加以区分。

聚集是不跨越事实的聚集是针对原始星型模型进⾏的汇总，为了获取和查询原始模型⼀致的结果， 聚集的维度和度量必须与原始模型保持⼀致，因此聚集是不跨事实的。横向钻取(交叉探查)是针对 多个事实基于⼀致性维度进⾏的分析，很多时候采⽤融合事实表，预先存放横向钻取的结果，从⽽ 提⾼查询性能。因此融合事实表是⼀种导出模式⽽不是聚集。
