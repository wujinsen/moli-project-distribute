# 接⼊层限流

接⼊层通常指请求流量的⼊⼝，该层的主要⽬的有：负载均衡、⾮法请求过滤、请求聚合、缓存、降 级、限流、A/B测试、服务质量监控等等，可以参考笔者写的《使⽤Nginx+Lua(OpenResty)开发⾼性 能Web应⽤》。

对于Nginx接⼊层限流可以使⽤Nginx⾃带了两个模块：连接数限流模块ngx_htp_limit_con_module 和漏桶算法实现的请求限流模块ngx_htp_limit_req_module。还可以使⽤OpenResty提供的Lua限流 模块lua-resty-limit-trafic进⾏更复杂的限流场景。

limit_con⽤来对某个KEY对应的总的⽹络连接数进⾏限流，可以按照如IP、域名维度进⾏限流。 limit_req⽤来对某个KEY对应的请求的平均速率进⾏限流，并有两种⽤法：平滑模式（delay）和允许 突发模式(nodelay)。

ngx_htp_limit_con_module limit_con是对某个KEY对应的总的⽹络连接数进⾏限流。可以按照IP来限制IP维度的总连接数，或者 按照服务域名来限制某个域名的总连接数。但是记住不是每⼀个请求连接都会被计数器统计，只有那 些被Nginx处理的且已经读取了整个请求头的请求连接才会被计数器统计。

配置示例：

=

htp { limit_con_zone$binary_remote_adr zone=adr:10m; limit_con_log_level error; limit_con_status 503;

.

server { .

location /limit {

limit_con adr 1; }

=

limit_con：要配置存放KEY和计数器的共享内存区域和指定KEY的最⼤连接数；此处指定的最⼤连接 数是1，表示Nginx最多同时并发处理1个连接； limit_con_zone：⽤来配置限流KEY、及存放KEY对应信息的共享内存区域⼤⼩；此处的KEY是 “$binary_remote_adr”其表示IP地址，也可以使⽤如$server_name作为KEY来限制域名级别的最⼤连 接数； limit_con_status：配置被限流后返回的状态码，默认返回503； limit_con_log_level：配置记录被限流后的⽇志级别，默认eror级别。

limit_con的主要执⾏过程如下所示： 1、请求进⼊后⾸先判断当前limit_con_zone中相应KEY的连接数是否超出了配置的最⼤连接数；

- 2.1、如果超过了配置的最⼤⼤⼩，则被限流，返回limit_con_status定义的错误状态码；

- 2.2、否则相应KEY的连接数加1，并注册请求处理完成的回调函数；

- 3、进⾏请求处理；

- 4、在结束请求阶段会调⽤注册的回调函数对相应KEY的连接数减1。


limt_con可以限流某个KEY的总并发/请求数，KEY可以根据需要变化。

按照IP限制并发连接数配置示例： ⾸先定义IP维度的限流区域：

=

limit_con_zone $binary_remote_adrzone=perip:10m;

=

接着在要限流的location中添加限流逻辑：

=

location /limit { limit_con perip 2; echo "123";

}

=

即允许每个IP最⼤并发连接数为2。

使⽤AB测试⼯具进⾏测试，并发数为5个，总的请求数为5个：

=

=

## 按照域名限制并发连接数配置示例：

⾸先定义域名维度的限流区域：

=

limit_con_zone $ server_name zone=perserver:10m;

=

接着在要限流的location中添加限流逻辑：

=

location /limit { limit_con perserver 2; echo "123";

}

=

即允许每个域名最⼤并发请求连接数为2；这样配置可以实现服务器最⼤连接数限制。

ngx_htp_limit_req_module limit_req是令牌桶算法实现，⽤于对指定KEY对应的请求进⾏限流，⽐如按照IP维度限制请求速率。

配置示例：

=

htp { limit_req_zone $binary_remote_adr zone=one:10m rate=1r/s; limit_con_log_level error; limit_con_status 503;

. server {

. location /limit {

limit_req zone=one burst=5 nodelay; }

=

limit_req：配置限流区域、桶容量（突发容量，默认0）、是否延迟模式（默认延迟）； limit_req_zone：配置限流KEY、及存放KEY对应信息的共享内存区域⼤⼩、固定请求速率；此处指定 的KEY是“$binary_remote_adr”表示IP地址；固定请求速率使⽤rate参数配置，⽀持10r/s和60r/m， 即每秒10个请求和每分钟60个请求，不过最终都会转换为每秒的固定请求速率（10r/s为每10毫秒处 理⼀个请求；60r/m，即每1 0毫秒处理⼀个请求）。 limit_con_status：配置被限流后返回的状态码，默认返回503； limit_con_log_level：配置记录被限流后的⽇志级别，默认eror级别。

limit_req的主要执⾏过程如下所示：

1、请求进⼊后⾸先判断最后⼀次请求时间相对于当前时间（第⼀次是0）是否需要限流，如果需要限 流则执⾏步骤2，否则执⾏步骤3；

- 2.1、如果没有配置桶容量（burst），则桶容量为0；按照固定速率处理请求；如果请求被限流，则直 接返回相应的错误码（默认503）；

- 2.2、如果配置了桶容量（burst>0）且延迟模式(没有配置nodelay)；如果桶满了，则新进⼊的请求被 限流；如果没有满则请求会以固定平均速率被处理（按照固定速率并根据需要延迟处理请求，延迟使 ⽤休眠实现）；

- 2.3、如果配置了桶容量（burst>0）且⾮延迟模式（配置了nodelay）；不会按照固定速率处理请求， ⽽是允许突发处理请求；如果桶满了，则请求被限流，直接返回相应的错误码；


- 3、如果没有被限流，则正常处理请求；

- 4、Nginx会在相应时机进⾏选择⼀些（3个节点）限流KEY进⾏过期处理，进⾏内存回收。

此处的限流都是单Nginx的，假设我们接⼊层有多个nginx，此处就存在和应⽤级限流相同的问题；那 如何处理呢？⼀种解决办法：建⽴⼀个负载均衡层将按照限流KEY进⾏⼀致性哈希算法将请求哈希到接 ⼊层Nginx上，从⽽相同KEY的将打到同⼀台接⼊层Nginx上；另⼀种解决⽅案就是使⽤Nginx+Lua （OpenResty）调⽤分布式限流逻辑实现。

lua-resty-limit-trafic 之前介绍的两个模块使⽤上⽐较简单，指定KEY、指定限流速率等就可以了，如果我们想根据实际情况 变化KEY、变化速率、变化桶⼤⼩等这种动态特性，使⽤标准模块就很难去实现了，因此我们需要⼀种 可编程来解决我们问题；⽽OpenResty提供了lua限流模块lua-resty-limit-trafic，通过它可以按照更复 杂的业务逻辑进⾏动态限流处理了。其提供了limit.con和limit.req实现，算法与nginx limit_con和 limit_req是⼀样的。

此处我们来实现ngx_htp_limit_req_module中的【场景2.2测试】，不要忘记下载lua-resty-limittrafic模块并添加到OpenResty的lualib中。

配置⽤来存放限流⽤的共享字典：

=

ngx.exit(error_status) end local key = ngx.var.binary_remote_adr -IP维度的限流

-流⼊请求，如果请求需要被延迟则delay > 0 local delay, err = lim:incoming(key, true) if not delay and err = "rejected" then-超出桶⼤⼩了

ngx.exit(error_status) end if delay > 0 then -根据需要决定是延迟或者不延迟处理

if nodelay then

-直接突发处理了 else

ngx.sl ep(delay) -延迟处理 end

end

即限流逻辑再nginx aces阶段被访问，如果不被限流继续后续流程；如果需要被限流要么sl ep⼀段 时间继续后续流程，要么返回相应的状态码拒绝请求。
