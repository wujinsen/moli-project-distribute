# 什么是merkle tree

假设你已经知道了什么是哈希算法以及哈希是⽤来⼲啥的。 ⽹络传输数据的时候，A收到B的传过来的⽂件，需要确认收到的⽂件有没有损坏。如何解决？ 有⼀种⽅法是B在传⽂件之前先把⽂件的hash结果给A，A收到⽂件再计算⼀次哈希然后和收到的哈希 ⽐较就知道⽂件有⽆损坏。 但是当⽂件很⼤的时候，往往需要把⽂件拆分很多的数据块各⾃传输，这个时候就需要知道每个数据 块的哈希值。怎么办呢？ 这种情况，可以在下载数据之前先下载⼀份哈希列表(hash list)，这个列表每⼀项对应⼀个数据块的哈 希值。对这个hash list拼接后可以计算⼀个根hash。实际应⽤中，我们只要确保从⼀个可信的渠道获取 正确的根hash，就可以确保下载正确的⽂件。 似乎很完美了。但是还不够好！ 上⾯基于hash list的⽅案这样⼀个问题： 有些时候我们获取(遍历)所有数据块的hash list代价⽐较⼤，只能获取部分节点的哈希。 有没有⼀种⽅法可以通过部分hash就能校验整个⽂件的完整性呢？ 答案是肯定的，merkle tree能做到。它⻓这样⼦:

特点如下:

- 1、数据结构是⼀个树，可以是⼆叉树，也可以是多叉树（本BLOG以⼆叉树来分析）

- 3、Merke Tree⾮叶⼦节点value是其所有⼦节点value的HASH值。 很明显，这种结构跟hash list相⽐较，根哈希不是⽤所有的数据块哈希拼接起来计算的，⽽是通过⼀个 层级的关系计算出来的。 在上图中，叶⼦节点node7的value（v7) = hash(f1),是f1⽂件的HASH;⽽其⽗亲节点node3的value = hash(v7, v8)，也就是其⼦节点node7 node8的值得HASH


## 其它应⽤场景

⽂件下载

假设我有两台机器，A和B，有⼀个⽂件从A传输到B。B⾸先获取可信的⽂件merkle tree，当⽂件下载 完毕后，B通过⾃⼰构建的merkle tree根节点和获取的根节点⽐较，如果不⼀致,通过这种⼆叉树的结 构可以在log(N)的复杂度快速定位到出错的数据块。

副本同步

⼀个集群⾥的所有机器，需要保持数据的同步，如果数据不⼀致，需要快速的定位到不⼀致的节点。 可以在每台机器上针对每个区间⾥的数据构造⼀棵Merkle Tree，这样，在两台机器间进⾏数据⽐对 时，从Merkle Tree的根节点开始进⾏⽐对，如果根节点⼀样，则表示两个副本⽬前是⼀致的，不再需 要任何处理；如果不⼀样，则遍历Merkle Tree，定位到不⼀致的节点也⾮常快速

什么是SPV

为了更好的解释，这⾥先插播⼀个概念，SPV。也就是中本聪描述到的“简化⽀付验证” 正是有了 SPV，才让区块链和⽐特币更加⼴泛的被传播。 我们⼤部分⼈在电脑安装的⽐特币钱包都是轻量级(⾮全节点)的，也就是本地并没有所有的区块数据 (上百G)。理论上来说，要验证⼀笔交易，钱包需要遍历所有的区块找到和该笔交易相关的所有交易进 ⾏逐个验证才是可靠的。 但是轻量级的钱包没有完整的数据，如何验证⼀笔⽀付的合法性呢? merkle tree就起到了关键的作⽤。 当然SPV有它的局限性(这个有空再写⽂章细讲)。
