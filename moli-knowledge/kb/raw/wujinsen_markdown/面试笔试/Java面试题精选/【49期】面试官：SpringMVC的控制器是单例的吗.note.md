# 总结

尽量不要在controler⾥⾯去定义属性，如果在特殊情况需要定义属性的时候，那么就在类上⾯加上注解 @Scope("prototype")改为多例的模式. 以前struts是基于类的属性进⾏发的，定义属性可以整个类通⽤，所以默认是多例，不然多线程访问肯定是共 ⽤类⾥⾯的属性值的，肯定是不安全的，但是springmvc是基于⽅法的开发，都是⽤形参接收值，⼀个⽅法结 束参数就销毁了，多线程访问都会有⼀块内存空间产⽣，⾥⾯的参数也是不会共⽤的，所有springmvc默认使 ⽤了单例.

所以controler⾥⾯不适合在类⾥⾯定义属性，只要controler中不定义属性，那么单例完全是安全的。 springmvc这样设计主要的原因也是为了提⾼程序的性能和以后程序的维护只针对业务的维护就⾏，要是 struts的属性定义多了，都不知道哪个⽅法⽤了这个属性，对以后程序的维护还是很麻烦的。 留⼀个问题：那他是线程安全的吗？知道的欢迎留⾔解答
