# B+树

B+树和⼆叉树、平衡⼆叉树⼀样，都是经典的数据结构。B+树由B树和索引顺序访问⽅法（ISAM，是不是很熟悉？对，这 也是MyISAM引擎最初参考的数据结构）演化⽽来，但是在实际使⽤过程中⼏乎已经没有使⽤B树的情况了。 B+树的定义⼗分复杂，因此只简要地介绍B+树：B+树是为磁盘或其他直接存取辅助设备⽽设计的⼀种平衡查找树，在B+树 中，所有记录节点都是按键值的⼤⼩顺序存放在同⼀层的叶节点中，各叶节点指针进⾏连接。 我们先来看⼀个B+树，其⾼度为2，每⻚可存放4条记录，扇出（fan out）为5。

![image 1](<B+树介绍.note_images/imageFile1.png>)

可以看出，所有记录都在叶节点中，并且是顺序存放的，如果我们从最左边的叶节点开始顺序遍历，可以得到所有键值的顺序 排序：5、10、15、20、25、30、50、55、60、65、75、80、85、90。

B+树的插⼊操作

B+树的插⼊必须保证插⼊后叶节点中的记录依然排序，同时需要考虑插⼊B+树的三种情况，每种情况都可能会导致不同的插 ⼊算法，如表5-1所示。

![image 2](<B+树介绍.note_images/imageFile2.png>)

我们⽤实例来分析B+树的插⼊，我们插⼊28这个键值，发现当前Leaf Page和Index Page都没有满，我们直接插⼊就可以 了。

![image 3](<B+树介绍.note_images/imageFile3.png>)

这次我们再插⼊⼀条70这个键值，这时原先的Leaf Page已经满了，但是Index Page还没有满，符合表5-1的第⼆种情况， 这时插⼊Leaf Page后的情况为50、55、60、65、70。我们根据中间的值60拆分叶节点。

![image 4](<B+树介绍.note_images/imageFile4.png>)

因为图⽚显示的关系，这次我没有能在各叶节点加上双向链表指针。最后我们来插⼊记录95，这时符合表5-1讨论的第三种情 况，即Leaf Page和Index Page都满了，这时需要做两次拆分。

![image 5](<B+树介绍.note_images/imageFile5.png>)

可以看到，不管怎么变化，B+树总是会保持平衡。但是为了保持平衡，对于新插⼊的键值可能需要做⼤量的拆分⻚（split） 操作，⽽B+树主要⽤于磁盘，因此⻚的拆分意味着磁盘的操作，应该在可能的情况下尽量减少⻚的拆分。因此，B+树提供了 旋转（rotation）的功能。 旋转发⽣在Leaf Page已经满了、但是其左右兄弟节点没有满的情况下。这时B+树并不会急于去做拆分⻚的操作，⽽是将记

录移到所在⻚的兄弟节点上。通常情况下，左兄弟被⾸先检查⽤来做旋转操作，这时我们插⼊键值70，其实B+树并不会急于 去拆分叶节点，⽽是做旋转，50，55，55旋转。

![image 6](<B+树介绍.note_images/imageFile6.png>)

可以看到，采⽤旋转操作使B+树减少了⼀次⻚的拆分操作，⽽这时B+树的⾼度依然还是2。
