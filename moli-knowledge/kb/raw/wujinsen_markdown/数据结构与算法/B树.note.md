常⻅的动态查找树有：⼆叉查找树（BST）、平衡⼆叉查找树（AVL）、红⿊树（RB-Tree）、Btree/B+-tree。

由于前⾯三种树都属于⼆叉树，因此树的⾼度为(log2N)。树查找的时间复杂度与树的⾼度有关， 因此要提⾼查找效率必须要降低树的⾼度，所以我们可以想到多叉树。

B树、B+树都是基于多叉树实现的。

# 磁盘的读/写原理和效率

磁盘块是磁盘中数据存储、检索的基本单位。同⼀个磁盘具有固定⼤⼩的磁盘块，⼀般为512字节

或4k字节。 磁盘上数据必须⽤⼀个三维地址唯⼀标示：柱⾯号、盘⾯号、块号(磁道上的盘块) 读/写磁盘上某⼀指定数据需要下⾯3个步骤：

(1) ⾸先移动臂根据柱⾯号使磁头移动到所需要的柱⾯上，这⼀过程被称为定位或查找

- (2) 如上图所示，所有磁头都定位到了10个盘⾯的10条磁道上。这时根据盘⾯号来确定指定盘⾯上

的磁道

- (3) 盘⾯确定以后，盘⽚开始旋转，将指定块号的磁道段移动⾄磁头下 经过上⾯三个步骤，指定数据的存储位置就被找到。这时就可以开始读/写操作了。


磁盘读取数据是以盘块(block)为基本单位的。位于同⼀盘块中的所有数据都能被⼀次性全部读取 出来。⽽磁盘IO代价主要花费在查找时间上。因此我们应该尽量将相关信息存放在同⼀盘块，同⼀磁 道中。或者⾄少放在同⼀柱⾯或相邻柱⾯上，以求在读/写信息时尽量减少磁头来回移动的次数，避免 过多的查找时间。

读写数据时，花费最⼤的是磁盘存取的时间。因此为了提⾼效率，我们必须降低磁盘查找存取的 次数。因此想到了多叉树，如B树、B+树、B*树。本⽂将主要介绍B树的原理和操作。

# B树

为了降低树的⾼度，B树的度⼀般都⾮常⼤。B树与红⿊树的相似之处在于，每棵含n个节点的B树 的⾼度为O(lgn)，但是可能⽐红⿊树的⾼度⼩得多。

内节点：⾮叶⼦节点 如果B树的内节点x包含n[x]个关键字，则x节点就有n[x]+1个孩⼦节点。节点x中的n[x]个关键字将x

所处理的关键字区间划分成n[x]+1个⼦区间。以根节点的左孩⼦节点为例，D、H两个关键字将该节点 所处理的关键字区间划分成3个⼦区间：

# B树的定义

B树必须满⾜：

- 1）每个节点x有以下域

- a）n[x]，存储节点中的关键字数

- b）keyi[x]，n[x]个关键字本身，以⾮降序⽅式存放，即key1[x] ≤ key2[x] ≤ …… ≤ keyn[x][x]

- c）leaf[x]，为TRUE时，表明节点是叶⼦节点。否则为FALSE，表明节点为内节点


- 2）每个内节点还包含n[x]+1个指向其孩⼦的指针，c1[x]、c2[x]、……、cn[x]+1[x]


- 3）每个内节点x中的n[x]个关键字对各⼦树中的关键字范围进⾏划分，n[x]个节点划分出n[x]+1个

区间（⼦树）

- 4）每个叶节点具有相同的深度，即树的⾼度h

- 5）除了上述的基本性质之外，还对B树的度有限制。若B树的最⼩度数为t ≥ 2，则


- a）每个节点（根节点除外）必须⾄少有 t-1 个关键字，即⾄少有t个⼦树

- b）每个节点最多有 2t-1 个关键字，即⾄少有2t个⼦树，此时节点是满的


t=2是最简单的B树，但是在实际应⽤中t的值要⼤得多。⼀般B树中的⼀个节点就占⽤磁盘中的⼀ 个块的内存（⼀般为512或4096字节）。

由于在查找时，我们在B树的每⼀层最多访问⼀个节点，因此查找的时间复杂度为O(h)。⽽⼀个节 点对应⼀个磁盘块，因此读取磁盘的次数也为O(h)。

若B树的度为t，则B树的⾼度 h ≤ logt((n+1)/2) ，⽐⼀般的⼆叉树读取磁盘的次数要少得多。

# 删除

- 1）如果要删除的关键字在叶⼦节点上，且叶⼦节点关键字数⼤于t，则可以直接删除。

- 2）但如果在内节点中，由于每⼀个key左右都有⼀个⼦树，删除后会违背B树的定义，因此必须进

⾏调整。

- 3）同时为了保证删除后每个节点⾄少有t-1个关键字，因此在查找过程中，保证递归的每个节点⾄


少有t个关键字。否则就要先对节点进⾏合并，才能继续向下递归查找。 同样以t=2为例，则每个节点关键字数为[t-1,2t-1]，即为[1,3] 因此具体的删除可以分为三种情况：

- 1）要删除的关键字在叶⼦节点上，且叶⼦节点关键字数⼤于t，则可以直接删除
