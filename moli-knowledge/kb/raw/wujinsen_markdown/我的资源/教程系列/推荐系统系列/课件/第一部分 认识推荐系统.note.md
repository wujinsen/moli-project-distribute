基础数据主要包括：

要推荐物品或内容的元数据，例如关键字，基因描述等；

系统⽤户的基本信息，例如性别，年龄等

⽤户对物品或者信息的偏好，根据应⽤本身的不同，可能包括⽤户对物品的评分，⽤户查看物品的 记录，⽤户的购买记录等。其实这些⽤户的偏好信息可以分为两类：

显式的⽤户反馈：这类是⽤户在⽹站上⾃然浏览或者使⽤⽹站以外，显式的提供反馈信息，例 如⽤户对物品的评分，或者对物品的评论。

隐式的⽤户反馈：这类是⽤户在使⽤⽹站是产⽣的数据，隐式的反应了⽤户对物品的喜好，例 如⽤户购买了某物品，⽤户查看了某物品的信息等等。

显式的⽤户反馈能准确的反应⽤户对物品的真实喜好，但需要⽤户付出额外的代价，⽽隐式的⽤户 ⾏为，通过⼀些分析和处理，也能反映⽤户的喜好，只是数 据不是很精确，有些⾏为的分析存在 较⼤的噪⾳。但只要选择正确的⾏为特征，隐式的⽤户反馈也能得到很好的效果，只是⾏为特征的 选择可能在不同的应⽤中有很 ⼤的不同，例如在电⼦商务的⽹站上，购买⾏为其实就是⼀个能很 好表现⽤户喜好的隐式反馈。

推荐引擎的分类 推荐引擎的分类可以根据很多指标进⾏区分：

根据⽬标⽤户进⾏区分：根据这个指标可以分为基于⼤众⾏为的推荐引擎和个性化推荐引擎。

根据⼤众⾏为的推荐引擎，对每个⽤户都给出同样的推荐，这些推荐可以是静态的由系统管理 员⼈⼯设定的，或者基于系统所有⽤户的反馈统计计算出的当下⽐较流⾏的物品。

个性化推荐引擎，对不同的⽤户，根据他们的⼝味和喜好给出更加精确的推荐，这时，系统需 要了解需推荐内容和⽤户的特质，或者基于社会化⽹络，通过找到与当前⽤户相同喜好的⽤ 户，实现推荐。

这是⼀个最基本的推荐引擎分类，其实⼤部分⼈们讨论的推荐引擎都是将个性化的推荐引擎，因为 从根本上说，只有个性化的推荐引擎才是更加智能的信息发现过程。

根据数据源进⾏区分：主要是根据数据之间的相关性进⾏推荐，因为⼤部分推荐引擎的⼯作原理还 是基于物品或者⽤户的相似集进⾏推荐。

根据系统⽤户的基本信息发现⽤户的相关程度，这种被称为基于⼈⼝统计学的推荐 （Demographic-based Recomendation）

根据推荐物品或内容的元数据，发现物品或者内容的相关性，这种被称为基于内容的推荐 （Content-based Recomendation）

根据⽤户对物品或者信息的偏好，发现物品或者内容本身的相关性，或者是发现⽤户的相关 性，这种被称为基于协同过滤的推荐（Colaborative Filtering-based Recomendation）。

根根据推荐模型进⾏区分：可以想象在海量物品和⽤户的系统中，推荐引擎的计算量是相当⼤的， 要实现实时的推荐务必需要建⽴⼀个推荐模型，关于推荐模型的建⽴⽅式可以分为以下⼏种：

基于物品和⽤户本身的，这种推荐引擎将每个⽤户和每个物品都当作独⽴的实体，预测每个⽤ 户对于每个物品的喜好程度，这些信息往往 是⽤⼀个⼆维矩阵描述的。由于⽤户感兴趣的物品 远远⼩于总物品的数⽬，这样的模型导致⼤量的数据空置，即我们得到的⼆维矩阵往往是⼀个 很⼤的稀疏矩阵。同 时为了减⼩计算量，我们可以对物品和⽤户进⾏聚类， 然后记录和计算⼀ 类⽤户对⼀类物品的喜好程度，但这样的模型⼜会在推荐的准确性上有损失。

基于关联规则的推荐（Rule-based Recomendation）：关联规则的挖掘已经是数据挖掘中的 ⼀个经典的问题，主要是挖掘⼀些数据的依赖关系，典型的场景就是“购物篮问题”，通过关联 规则的挖掘，我们可以找到哪些物品经常被同时购买，或者⽤户购买了⼀些物品后通常会购买 哪些其他的物品，当我们挖掘出这些关联规则之后，我们可以基于这些规则给⽤户进⾏推荐。

基于模型的推荐（Model-based Recomendation）：这是⼀个典型的机器学习的问题，可以 将已有的⽤户喜好信息作为训练样本，训练出⼀个预测⽤户喜好的模型，这样以后⽤户在 进⼊ 系统，可以基于此模型计算推荐。这种⽅法的问题在于如何将⽤户实时或者近期的喜好信息反 馈给训练好的模型，从⽽提⾼推荐的准确度。

其实在现在的推荐系统中，很少有只使⽤了⼀个推荐策略的推荐引擎，⼀般都是在不同的场景下使 ⽤不同的推荐策略从⽽达到最好的推荐效果，例如 Amazon 的推荐，它将基于⽤户本身历史购买 数据的推荐，和基于⽤户当前浏览的物品的推荐，以及基于⼤众喜好的当下⽐较流⾏的物品都在不 同的区域推荐给⽤户，让⽤户 可以从全⽅位的推荐中找到⾃⼰真正感兴趣的物品。

第⼀代协同过滤技术是基于⽤户的协同过滤算法，基于⽤户的协同过滤算法在推荐系统中获得了极 ⼤的成功，但它有⾃身的局限性。因为基于⽤户的协同过滤算法先计算的是⽤户与⽤户的相似度 （兴趣相投，⼈以群分物以类聚），然后将相似度⽐较接近的⽤户A购买的物品推荐给⽤户B，专 业的说法是该算法⽤最近邻居（nearest-neighbor）算法找出⼀个⽤户的邻居集合，该集合的⽤户 和该⽤户有相似的喜好，算法根据邻居的偏好对该⽤户进⾏预测。 基于⽤户的推荐逻辑有两个问题：冷启动与计算量巨⼤。基于⽤户的算法只有已经被⽤户选择（购 买）的物品才有机会推荐给其他⽤户。在⼤型电商⽹站上来讲，商品的数量实在是太多了，没有被 相当数量的⽤户购买的物品实在是太多了，直接导致没有机会推荐给⽤户了，这个问题被称之为协 同过滤的“冷启动”。另外，因为计算⽤户的相似度是通过⽬标⽤户的历史⾏为记录与其他每⼀个⽤ 户的记录相⽐较的出来的，对于⼀个拥有千万级活跃⽤户的电商⽹站来说，每计算⼀个⽤户都涉及 到了上亿级别的计算，虽然我们可以先通过聚类算法经⽤户先分群，但是计算量也是⾜够的⼤。

其他推荐算法

基于⼈⼝统计学的推荐：基于⼈⼝统计学的推荐机制（Demographic-based Recomendation）是 ⼀种最易于实现的推荐⽅法，它只是简单的根据系统⽤户的基本信息发现⽤户的相关程度，然后将 相似⽤户喜爱的其他物品推荐给当前⽤户。基于⼈⼝统计学的推荐机制的好处在于：因为不使⽤当 前⽤户对物品的喜好历史数据，所以对于新⽤户来讲没有“冷启动（Cold Start）”的问题。这个⽅法 不依赖于物品本身的数据，所以这个⽅法在不同物品的领域都可以使⽤，它是领域独⽴的 （domain-independent） 基于内容的推荐：基于内容的推荐是在推荐引擎出现之初应⽤最为⼴泛的推荐机制，它的核⼼思想 是根据推荐物品或内容的元数据，发现物品或者内容的相关性，然后基于⽤户以往的喜好记录，推 荐给⽤户相似的物品。基于内容的推荐机制的好处在于它能很好的建模⽤户的⼝味，能提供更加精 确的推荐。但它也存在以下⼏个问题：

需要对物品进⾏分析和建模，推荐的质量依赖于对物品模型的完整和全⾯程度。在现在的应⽤ 中我们可以观察到关键词和标签（Tag）被认为是描述物品元数据的⼀种简单有效的⽅法；

物品相似度的分析仅仅依赖于物品本身的特征，这⾥没有考虑⼈对物品的态度；

因为需要基于⽤户以往的喜好历史做出推荐，所以对于新⽤户有“冷启动”的问题。

虽然这个⽅法有很多不⾜和问题，但他还是成功的应⽤在⼀些电影，⾳乐，图书的社交站点，有些 站点还请专业的⼈员对物品进⾏基因编码，⽐如潘多拉，在⼀份报告中说道，在潘多拉的推荐引擎 中，每⾸歌有超过 10 个元数据特征，包括歌曲的⻛格，年份，演唱者等等。

混合的推荐机制 在现⾏的 Web 站点上的推荐往往都不是单纯只采⽤了某⼀种推荐的机制和策略，他们往往是将多个

⽅法混合在⼀起，从⽽达到更好的推荐效果。关于如何组合各个推荐机制，这⾥讲⼏种⽐较流⾏的组 合⽅法。

加权的混合（Weighted Hybridization）: ⽤线性公式（linear formula）将⼏种不同的推荐按照⼀定 权重组合起来，具体权重的值需要在测试数据集上反复实验，从⽽达到最好的推荐效果。

切换的混合（Switching Hybridization）：前⾯也讲到，其实对于不同的情况（数据量，系统运⾏ 状况，⽤户和物品的数⽬等），推荐策略可能有很⼤的不同，那么切换的混合⽅式，就是允许在不 同的情况下，选择最为合适的推荐机制计算推荐。

分区的混合（Mixed Hybridization）：采⽤多种推荐机制，并将不同的推荐结果分不同的区显示给 ⽤户。其实，Amazon，当当⽹等很多电⼦商务⽹站都是采⽤这样的⽅式，⽤户可以得到很全⾯的 推荐，也更容易找到他们想要的东⻄。

分层的混合（Meta-Level Hybridization）: 采⽤多种推荐机制，并将⼀个推荐机制的结果作为另⼀ 个的输⼊，从⽽综合各个推荐机制的优缺点，得到更加准确的推荐。

推荐系统的应⽤场景

捆绑销售 (Frequently Bought Together): 采⽤数据挖掘技术对⽤户的购买⾏为进⾏分析，找到经常 被⼀起或同⼀个⼈购买的物品集，进⾏捆绑销售，这是⼀种典型的基于项⽬的协同过滤推荐机制。

别⼈购买 / 浏览的商品 (Customers Who Bought/Se This Item Also Bought/Se): 这也是⼀个典型 的基于项⽬的协同过滤推荐的应⽤，通过社会化机制⽤户能更快更⽅便的找到⾃⼰感兴趣的物品。

归⼀化：如前⾯讲到的，在计算⽤户对物品的喜好程度时，可能需要对不同的⾏为数据进⾏加 权。但可以想象，不同⾏为的数据取值可能相差很 ⼤，⽐如，⽤户的查看数据必然⽐购买数据 ⼤的多，如何将各个⾏为的数据统⼀在⼀个相同的取值范围中，从⽽使得加权求和得到的总体 喜好更加精确，就需要我们 进⾏归⼀化处理。最简单的归⼀化处理，就是将各类数据除以此类 中的最⼤值，以保证归⼀化后的数据取值在 [0,1] 范围中。

基于⽤户的 CF 的基本思想相当简单，基于⽤户对物品的偏好找到相邻邻居⽤户，然后将邻居⽤户 喜欢的推荐给当前⽤户。计算上，就是将⼀个⽤户对所有物品的偏好作为⼀个向量 来计算⽤户之 间的相似度，找到 K 邻居后，根据邻居的 相似度权重以及他们对物品的偏好，预测当前⽤户没有偏好的未涉及物品，计算得到⼀个排序的物 品列表作为推荐。图 2 给出了⼀个例⼦，对于⽤户 A，根据⽤户的历史偏好，这⾥只计算得到⼀ 个邻居 - ⽤户 C，然后将⽤户 C 喜欢的物品 D 推荐给⽤户 A。

User CF vs. Item CF

计算复杂度

Item CF 和 User CF 是基于协同过滤推荐的两个最基本的算法，User CF 是很早以前就提出来 了，Item CF 是从 Amazon 的论⽂和专利发表之后（201 年左右）开始流⾏，⼤家都觉 得 Item CF 从性能和复杂度上⽐ User CF 更优，其中的⼀个主要原因就是对于⼀个在线⽹ 站，⽤户的数量往往⼤⼤超过物品的数量，同时物品的数据相对稳定，因此计算物品的相似度 不但计算量较⼩，同时 也不必频繁更新。但我们往往忽略了这种情况只适应于提供商品的电 ⼦商务⽹站，对于新闻，博客或者微内容的推荐系统，情况往往是相反的，物品的数量是海 量 的，同时也是更新频繁的，所以单从复杂度的⻆度，这两个算法在不同的系统中各有优 势，推荐引擎的设计者需要根据⾃⼰应⽤的特点选择更加合适的算法。

适⽤场景

在⾮社交⽹络的⽹站中，内容内在的联系是很重要的推荐原则，它⽐基于相似⽤户的推荐原则 更加有效。⽐如在购书⽹站上，当你看⼀本书的时候，推荐引擎 会给你推荐相关的书籍，这 个推荐的重要性远远超过了⽹站⾸⻚对该⽤户的综合推荐。可以看到，在这种情况下， Item CF 的推荐成为了引导⽤户浏览的重要⼿段。同时 Item CF 便于为推荐做出解释，在⼀个 ⾮社交⽹络的⽹站中，给某个⽤户推荐⼀本书，同时给出的解释是某某和你有相似兴趣的⼈也 看了这本书，这很难让⽤户信服，因为⽤ 户可能根本不认识那个⼈；但如果解释说是因为这 本书和你以前看的某本书相似，⽤户可能就觉得合理⽽采纳了此推荐。相反的，在现今很流⾏ 的社交⽹络站点中，User CF 是⼀个更不错的选择，User CF 加上社会⽹络信息，可以增加⽤ 户对推荐解释的信服程度。

推荐多样性和精度

研究推荐引擎的学者们在相同的数据集合上分别⽤ User CF 和 Item CF 计算推荐结果，发现推荐 列表中，只有 50% 是⼀样的，还有 50% 完全不同。但是这两个算法确有相似的精度，所以可以 说，这两个算法是很互补的。 关于推荐的多样性，有两种度量⽅法： 第⼀种度量⽅法是从单个⽤户的⻆度度量，就是说给定⼀个⽤户，查看系统给出的推荐列表是否多 样，也就是要⽐较推荐列表中的物品之间两两的相似度，不 难想到，对这种度量⽅法， Item CF 的多样性显然不如 User CF 的好，因为 Item CF 的推荐就是和以前看的东⻄最相似的。

第⼆种度量⽅法是考虑系统的多样性，也被称为覆盖率 (Coverage)，它是指⼀个推荐系统是 否能够提供给所有⽤户丰富的选择。在这种指标下，Item CF 的多样性要远远好于 User CF, 因 为 User CF 总是倾向于推荐热⻔的，从另⼀个侧⾯看，也就是说，Item CF 的推荐有很好的新 颖性，很擅⻓推荐⻓尾⾥的物品。所以，尽管⼤多数情况，Item CF 的精度略⼩ 于 User CF， 但如果考虑多样性，Item CF 却⽐ User CF 好很多。

如果你对推荐的多样性还⼼存疑惑，那么下⾯我们再举个实例看看 User CF 和 Item CF 的多 样性到底有什么差别。 ⾸先，假设每个⽤户兴趣爱好都是⼴泛的，喜欢好⼏个领域的东⻄，不过每个⽤户肯定也有⼀ 个主要的领域，对这个领域会⽐其他领域更加关⼼。 给定⼀个⽤户，假设他喜欢 3 个领域 A,B,C，A 是他喜欢的主要领域，这个时候我们来 看 User CF 和 Item CF 倾向于做出什么推荐：如果⽤ User CF, 它会将 A,B,C 三个领域中⽐较 热⻔的东⻄推荐给⽤户；⽽如果⽤ ItemCF，它会基本上只推荐 A 领域的东⻄给⽤户。所以我 们看到因为 User CF 只推荐热⻔的，所以它在推荐⻓尾⾥项⽬⽅⾯的能⼒不⾜； ⽽ Item CF 只推荐 A 领域给⽤户，这样他有限的推荐列表中就可能包含了⼀定数量的不热⻔ 的⻓尾物品，同时 Item CF 的推荐对这个⽤户⽽⾔，显然多样性不⾜。但是对整个系统⽽⾔， 因为不同的⽤户的主要兴趣点不同，所以系统的覆盖率会⽐较好。 从上⾯的分析，可以很清晰的看到，这两种推荐都有其合理性，但都不是最好的选择，因此他 们的精度也会有损失。其实对这类系统的最好选择是，如果系统 给这个⽤户推荐 30 个物品， 既不是每个领域挑选 10 个最热⻔的给他，也不是推荐 30 个 A 领域的给他，⽽是⽐如推 荐 15 个 A 领域的给他，剩下的 15 个从 B,C 中选择。所以结合 User CF 和 Item CF 是最优的 选择，结合的基本原则就是当采⽤ Item CF 导致系统对个⼈推荐的多样性不⾜时，我们通过加 ⼊ User CF 增加个⼈推荐的多样性，从⽽提⾼精度，⽽当因为采⽤ User CF ⽽使系统的整体 多样性不⾜时，我们可以通过加⼊ Item CF 增加整体的多样性，同样同样可以提⾼推荐的精 度。

⽤户对推荐算法的适应度

前⾯我们⼤部分都是从推荐引擎的⻆度考虑哪个算法更优，但其实我们更多的应该考虑作为推 荐引擎的最终使⽤者 - 应⽤⽤户对推荐算法的适应度。 对于 User CF，推荐的原则是假设⽤户会喜欢那些和他有相同喜好的⽤户喜欢的东⻄，但如果 ⼀个⽤户没有相同喜好的朋友，那 User CF 的算法的效果就会很差，所以⼀个⽤户对的 CF 算 法的适应度是和他有多少共同喜好⽤户成正⽐的。 Item CF 算法也有⼀个基本假设，就是⽤户会喜欢和他以前喜欢的东⻄相似的东⻄，那么我们 可以计算⼀个⽤户喜欢的物品的⾃相似度。⼀个⽤户喜欢物品的⾃相似度⼤，就 说明他喜欢 的东⻄都是⽐较相似的，也就是说他⽐较符合 Item CF ⽅法的基本假设，那么他对 Item CF 的 适应度⾃然⽐较好；反之，如果⾃相似度⼩，就说明这个⽤户的喜好习惯并不满⾜ Item CF ⽅ 法的基本假设，那么对于这种⽤户，⽤ Item CF ⽅法做出好的推荐的可能性⾮常低。
