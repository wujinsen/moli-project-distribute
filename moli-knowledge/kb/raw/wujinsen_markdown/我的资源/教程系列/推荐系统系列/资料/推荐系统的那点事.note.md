# 推荐系统的误区

回想起来，我也算是国内接触推荐系统较早的⼈之⼀了，最近和⼈聊天，觉得不少⼈对推荐系统有所 误解，以为需要多么⾼⼤上的算法才能搭建起来的，我只想说我经常说的那句话【不是这样的】，所 以有了这篇⽂章。 第⼀次接触【推荐系统】是在两年前在某⾼校的互联⽹信息处理实验室的时候，那时候，【机器学 习】和【⼤数据】都是新概念，但是差不多半年后，【⼤数据】的概念就开始⻛靡全球了，到现在已 经被爆炒得⾯⽬全⾮。 那年还因此买了⼀本项亮的书《推荐系统实践》，那本书和现在的很多热⻔书籍⼀样，都是跟着概念 热起来的。 虽然有⼀些作者⾃⼰的实战经验在⾥⾯，但是总体上来说并没有太多值得重复翻开的地 ⽅。 ⼏乎所有宣扬【推荐系统】的⼈，都要拿【啤酒和尿布】，【亚⻢逊推荐占营收20%】之类的经典例 ⼦来说⼒证推荐系统的⽜逼之处。到处宣扬【推荐系统】插上【机器学习】等算法的翅膀，就能让电 ⼦商务变得精准⽆⽐，能智能的猜出⽤户想买的东⻄。 殊不知，其实这两个例⼦和所谓的【算法】其实关系不⼤。

- 1. 啤酒和尿布

⾸先是【啤酒和尿布】，超市的⼈员发现买啤酒的男⼈容易顺⼿买尿布。这其实是⼀种数据分析，是 根据数据统计加上⼈⼯分析得出，是⼀种以经验来改善销售的⾏为。和【机器学习】【数据挖掘】等 算法的关系不⼤。 刚接触【推荐系统】的时候，【协同过滤算法】⼤热， 我也曾经迷恋得研究过该算 法，以为发现了什么宝⻉⼀样。但是实际上，在⼯程中【协同过滤】出来的效果往往惨不忍睹，所谓 的【算法⼯程师】每天能做的就是在那调整【协同过滤】算法的相关参数，然后看看第⼆天的点击率 有没有上升。然后调整到最后你会发现，⽜逼哄哄的【协同过滤】其实还不如简简单单的【看了⼜ 看】效果来的好，虽然协同过滤算法本质上也是⼀种【看了⼜看】的思想。

- 2. 亚⻢逊的推荐系统


亚⻢逊的推荐系统占了营收⽐，我记得是20%，不知道现在上升了还是下降了。这个说辞会让很多⼈ 误以为只要你搞好了推荐系统，你的营收就能上升20%以上⼀样。其实不然，对于亚⻢逊来说，为什 么推荐能起到这么⾼的销量，⼀个很重要的原因在于，【亚⻢逊的⾸⻚点击率⾼的部分位置划分给了 推荐系统的】，从⼴告学上讲，⼴告位置的好坏极⼤的决定了⼴告的销量。这个很容易理解，假设你 的产品的⼴告牌能挂上天安⻔城楼的话，你觉得你还需要担⼼该产品的销量吗？

当然不可否定的是亚⻢逊的推荐系统应该是很⽜逼的，但是这并不说明他们采⽤的【推荐算法】⾮常 ⽜逼。推荐系统我认为其实和搜索系统并⽆太⼤差异，我⼀直认为推荐系统其实只是⼀个个性化的搜 索引擎。之前在【秘密】上很⽕的有个爆料是：“360搜索的Rank刚开始就是⽤【机器学习】的算法去 做，屎⼀样的效果，是我把百度的基于规则的算法偷过去之后才变好的。” ，这个爆料出来不少⼈讽刺 【基于规则】，觉得这是在⿊百度的算法。 其实不是这样的，记得当时阿⾥搜索挖了⼀个⾕歌搜索的 员⼯，该⼈在阿⾥分享的时候就说过：【⾕歌的搜索效果⽐别⼈好的原因就是规则库⽜逼，关于算法 使⽤的都是成熟的⼈尽皆知的算法，并没什么新奇酷的算法】。 可能也是这个原因，⾕歌研究院的科 学家⼏乎全是【⼯程师背景】出身的。还记得上次【 CF推荐系统前⾔讲座】，刚开始叫了⼏个学院 派的讲师在那⼤讲特讲各种酷炫掉渣天的算法，然后淘宝的⼤数据负责⼈⻋品觉 上台之后直接来了句 【我们实验出各种算法效果不太好，还不如最基本的 关联规则 效果来的好】直接把前⾯的学院派专家 们打脸打得都肿了。

# 我⼼⽬中的推荐系统

不管是电商，或者是新闻，都有【个性化推荐】和【热⻔推荐】的取舍。⼀个商品热⻔或者点击量⾼ 是有其原因的。所以将热⻔的东⻄推荐给⽤户是⾮常合情合理的，因为既然热⻔，也侧⾯说明了很⼤ 概率上该⽤户也会喜欢该商品。⽽【个性化推荐】本质上是为了解决【⻓尾】问题，把那些不热⻔的 东⻄，但是很可能符合某特定⽤户品味的商品【挖掘】出来，推荐给特定的⽤户群。 ⾸先，在推荐中，醒⽬的推荐位应该是【热⻔推荐】或者【⼈⼯推荐】，【⼈⼯推荐】是指⽐如在体 育新闻中，巴萨夺冠之类的⼤新闻是直接让编辑来【⼈⼯推荐】即可，就是此新闻⼀出，⻢上登上头 条，⽽不是在那磨磨唧唧的计算特征值，计算相似度，计算是否符合⽤户兴趣。 对于推荐中的【冷启 动】，最理想的推荐就是【相关推荐】。说到这⾥，整个推荐系统的 80% 已经搭建完毕，【热⻔推荐

+⼈⼯推荐+相关推荐】，这三者都是【个性化】都没什么关系，也算法关系也不⼤，但是这三者效果 的好坏就决定了整个系统推荐效果好坏的 80% 。好多⼈连最基本的这三者都没有做好，就开始想⼀步 登天，很可惜，这样的捷径是不存在的。 接下来是 20% 的【个性化】的做法，如上所说，个性化是 为了解决【⻓尾】问题，正是因为⻓尾占商品的 20% ，所以在此我认为【个性化】其实也只有 20% 。要解决个性化，⾸先就是要对⽤户分析，最成熟的办法就是对⽤户打标签（是否让你想起来社交⽹ 络为什么经常让你选⽤合适的标签描述⾃⼰，没错，就是为了分析你）。 其实，给⽤户打标签，逼格更⾼的说法叫【⽤户特征提取】或者【⽤户⾏为分析】。说到这两个词， 那些所谓的算法⼯程师可能就会开始扯什么⾼⼤上的算法，机器学习，⾃然语⾔处理，数据挖掘等各 种算法。其实在我看来，算法很⼤情况根本派不上⽤场，我认为这⽅⾯的关键在于【数据统计 + ⼈⼯ 分析】。将⽤户的浏览记录等记录下来，统计他最常点击的东⻄，最常去的频道，然后给他打上这些 频道或者商品的标签。或者收集更详细的信息，⽐如年龄，打上【⻘少年，男⼈，⼥⼈，⽼⼈】等标 签，根据这些标签进⾏推荐。⽐如当推荐护肤的商品时，就可以偏向于⼥⼈，推荐运动产品时，就可 以偏向于男⼈和⻘少年，推荐保健品时，就可以偏向于⽼年⼈。所以，光看年龄这个标签的维度，就 可以做很多⽂章。所以标签库的设计和积累，是⾮常⼴泛和重要的，⽽这⽅⾯需要⼤量依赖于【⼈⼯ 分析】，⽽不是看论⽂调算法能做到的。 就好⽐现在的中⽂分词，拼到最后⼤家都在⽐词库的积累， 谁的词库好，谁的效果就好，【搜狗】的【拼⾳输⼊法】效果好也是因为词库⽐别⼈好。

最后就是根据标签的定向推荐，这个推荐概率是有【权重设置】在⾥⾯，就⽐如刚才对年龄这个维度 的权重，是需要给予对应的权重值，如何给定呢？其实就是【拍脑袋】，当然，如果有某些公司已经 得出经验值了直接可以拿来⽤就会更好。但是在拍完脑袋之后需要做的就是观察点击率变化，查Bad Case，然后再对权重进⾏调整，也就是根据评测和反馈来调整，没有【评测和反馈】，整个系统等于 是⼀个⿊盒，谈何优化？在我看来，【推荐系统】本质上⾸先是⼀个系统，需要不断的对各种效果进 ⾏【评测】，查各种【Bad Case】，⽽这些都不是看论⽂可以学到的东⻄。
