对⽐Hadop的批处理，Storm是个实时的、分布式以及具备⾼容错的计算系统。 同Hadop⼀样Storm也可以处理⼤批量的数据，然⽽Storm在保证⾼可靠性的前提下还可以让处理进 ⾏的更加实时;也就是说，所有的信息都会被处理。 Storm同样还具备容错和分布计算这些特性，这就让Storm可以扩展到不同的机器上进⾏⼤批量的数据 处理。他同样还有以下的这些特性： 易于扩展。对于扩展，你只需要添加机器和改变对应的topology(拓扑)设置。Storm使⽤Hadop Zokeper进⾏集群协调，这样可以充分的保证⼤型集群的良好运⾏。 每条信息的处理都可以得到保证。 Storm集群管理简易。 Storm的容错机能：⼀旦topology递交，Storm会⼀直运⾏它直到topology被废除或者被关闭。⽽在执 ⾏中出现错误时，也会由Storm重新分配任务。 尽管通常使⽤Java，Storm中的topology可以⽤任何语⾔设计。

Storm和Hadop的区别

- 1，⾯向的领域不同，Hadop⾯向基于调度的离线计算，Storm⾯向基于内存流转的实时计算。


- 2，数据存储的介质不同，Hadop的数据存储在⽂件系统中，⼀批⼀批的存储，Strom的数据存储在 内存中，并被源源不断的产⽣。例⼦：有⽤⽔需求，⼀桶⼀桶的挑是离线计算，打开⽔⻰头是流式计 算。

- 3，Hadop是磁盘级计算，进⾏计算时，数据在磁盘上，需要读写磁盘；Storm是内存级计算，数据 直接通过⽹络导⼊内存。读写内存⽐读写磁盘速度快n个数量级。

Topology：storm中运⾏的⼀个实时应⽤程序，因为各个组件间的消息流动形成逻辑上的⼀个拓扑结 构。 Spout：在⼀个topology中产⽣源数据流的组件。通常情况下spout会从外部数据源中读取数据，然后 转换为topology内部的源数据。Spout是⼀个主动的⻆⾊，其接⼝中有个nextTuple()函数，storm框架 会不停地调⽤此函数，⽤户只要在其中⽣成源数据即可。 Bolt：在⼀个topology中接受数据然后执⾏处理的组件。Bolt可以执⾏过滤、函数操作、合并、写数据 库等任何操作。Bolt是⼀个被动的⻆⾊，其接⼝中有个execute(Tuple input)函数,在接受到消息后会调 ⽤此函数，⽤户可以在其中执⾏⾃⼰想要的操作。 Tuple：⼀次消息传递的基本单元。本来应该是⼀个key-value的map，但是由于各个组件间传递的 tuple的字段名称已经事先定义好，所以tuple中只要按序填⼊各个value就⾏了，所以就是⼀个value list. Stream：源源不断传递的tuple就组成了stream。 Stream grouping：即消息的partition⽅法。Storm中提供若⼲种实⽤的grouping⽅式，包括shufle, fields hash, al, global, none, direct和localOrShufle等 Stream Grouping定义了⼀个流在Bolt任务间该如何被切分。这⾥有Storm提供的6个StreamGrouping 类型：

- 1. 随机分组(Shufle grouping)：随机分发tuple到Bolt的任务，保证每个任务获得相等数量的tuple。

- 2. 字段分组(Fields grouping)：根据指定字段分割数据流，并分组。例如，根据“user-id”字段，相同 “user-id”的元组总是分发到同⼀个任务，不同“user-id”的元组可能分发到不同的任务。

- 3. 全部分组(Al grouping)：tuple被复制到bolt的所有任务。这种类型需要谨慎使⽤。

- 4. 全局分组(Global grouping)：全部流都分配到bolt的同⼀个任务。明确地说，是分配给ID最⼩的那个 task。


- 5. ⽆分组(None grouping)：你不需要关⼼流是如何分组。⽬前，⽆分组等效于随机分组。但最终， Storm将把⽆分组的Bolts放到Bolts或Spouts订阅它们的同⼀线程去执⾏(如果可能)。

- 6. 直接分组(Direct grouping)：这是⼀个特别的分组类型。元组⽣产者决定tuple由哪个元组处理者任 务接收。
