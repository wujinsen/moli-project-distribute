# 从哈希存储到Bloom Filter

焦萌 207年1⽉28⽇

先解释⼀下什么是哈希函数。哈希函数简单来说就是⼀种映射，它可取值的范围（定义域）通常很 ⼤，但值域相对较⼩。哈希函数所作的⼯作就是将⼀个很⼤定义域内的值映射到⼀个相对较⼩的值域 内。

传统的哈希存储

假设要哈希的集合为S，它有n个元素。传统的哈希⽅法是，将哈希区域组织成h（h > n）个格⼦的列 表，每⼀个格⼦都能存储S中的⼀个元素。存储时将S中的每⼀个元素映射到{0, 1, … , h-1}的范围内， 然后以这个值为索引将此元素存储到对应的格⼦内。由于哈希函数将⼀个⼤集合映射到⼀个⼩集合 中，所以存在将⼤集合中的多个元素映射到同⼀位置的情况，这就是所谓的碰撞（Colision）。当碰撞 发⽣时，有多种策略可供选择，⽐如⽤链表将映射到同⼀位置的元素串起来，或者在碰撞发⽣时再进 ⾏哈希映射直到找到空位为⽌等等。 传统的哈希⽅法不会发⽣错误，⽽且存储的元素还可以复原。如果哈希函数选择得当，碰撞出现的情 况⽐较少，那么查找某⼀个元素也很快。但是，如果你哈希某个集合只是为了判断某个元素是否在这 个集合中，那么你会发现好像存储整个集合有点浪费。按传统的哈希⽅法判断某个元素是否属于集合 时，会把这个元素和它映射位置上的元素进⾏匹配，如果完全匹配则说明属于集合，如果不匹配则不 属于。在绝⼤部分查找都不能匹配的情况下（这常常是实际中的情况），我们会发现匹配的过程经常 ⽤不到整个元素，因为元素的⼀部分就可以判断不匹配了。基于“部分信息就能判断不匹配”这个思路， Burton Bl om（Bl om Filter的发明者）提出了⼀种改进的⽅法。

改进的哈希存储

在这种改进的⽅法中，哈希区域和前⾯⼀样仍然被组织成格⼦的列表。但这次并不直接将集合元素存 在格⼦⾥，⽽是将每⼀个元素编码然后将编码存在格⼦⾥。假设每个集合元素要占b位，编码后要占c （c < b）位。由于编码位数少于元素位数，不同元素的编码有可能相同，因此在查找元素时可能会出 现错误。编码位数取决于你期望的错误率：编码位数越多，错误就越少，反之则越⼤；当错误少到⼀ 定程度（⼤约2-b），编码位数就⾜以存下整个元素，因此就变回了传统的哈希存储。 这种⽅法对传统的哈希存储进⾏了改良，允许⽤户在错误率和存储空间之间作权衡。这⾥我们已经能 够看到Bl om Filter的⼀点端倪。如果说这种⽅法已经孕育了“正确率换空间”的思想的话，那么Bl om Filter更是这个思想的⼤胆实践，它完全摆脱了传统的哈希存储⽅法，在存储空间使⽤和减少错误率⽅ ⾯又进了⼀步。

Bl om Filter

在Bl om Filter中，哈希区域的每⼀位都被当成是独⽴的可寻址的单元。在对集合元素进⾏编码时，同 时使⽤若⼲个独⽴的哈希函数，将每⼀个哈希函数映射的地址都置为1。这种编码⽅法可谓是另辟蹊 径，摆脱了原来⼀个格⼦⼀个格⼦的存储⽅法。在改进的哈希存储中，编码位数是和正确率交换的筹 码，⽽在Bl om Filter中，筹码变成了哈希函数的个数以及整个哈希区域（即位数组）的⼤⼩。如果想 具体知道合适的哈希函数个数和位数组⼤⼩，请参阅第⼀篇Bl om Filter概念和原理。

和前⾯两种哈希存储⽅法相⽐，Bloom Filter最⼤的优势⾃然是它的空间效率。另外，由于Bloom Filter 不⽤处理碰撞（Collision），因此它在增加或查找集合元素时所⽤的时间完全恒定（哈希函数的计算时 间），⽆论集合元素本⾝有多⼤，也⽆论多少集合元素已经加⼊到了位数组中。由于Bloom Filter和改 进的哈希存储都对集合元素进⾏了编码，因此想要从哈希区域中恢复集合元素并不容易。但同时，如 果你不想让别⼈直接看到集合元素，这样的编码处理倒可以看成是⼀种加密，有效保护了你的隐私。

Bl om Filter很⼤的⼀个缺点就是不能删除元素。由于Bl om Filter不处理碰撞，有可能多个哈希函数都 映射到了同⼀位，因此不能简单地在删除时将1置为0。后⾯我们会看到，Counting Bl om Filter通过将 每⼀位扩展为⼀个Counter来解决这⼀问题。
