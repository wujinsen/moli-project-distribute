字符集、字符编码

- 1.⽂件分为⽂本⽂件和⼆进制⽂件﹐不过本质都⼀样﹐都是些01。
- 2.计算机存储设备存储的0或1﹐称为计算机的⼀个⼆进制位(bit)。
- 3.⼆进制⽂件的0和1有专⻔的应⽤程序来读﹐所以它们没有什么乱不乱码的问题﹐只要该程序认得就 ⾏。(像doc,xls,exe,dl等)
- 4.⽂本⽂件就不⼀样了﹐notepad要认识它﹐vs.net要认识它,UE也要认识它…所以它们就要有⼀个标 准。这个标准的原理其实很简单﹐就是把所有的字符都给它⼀个序号﹐然后根据这个序号来找字符就 可以了。这个东东就是编码表,也叫字符集(charset)。
- 5.⽂本⽂件存的都是字符﹐如﹕A,?,@,x。很明显⼀个bit不能表示﹐刚好计算机的存储单位–字节(byte) 就是多个字节(1个byte=8个bit),因此⽤byte来表示字符就理所当然了。


- 6. 第⼀个编码表–ASCI码很快产⽣﹐很简单﹐就是⽤⼀个byte来表示⼀个字符(最⾼位置0),总共能存储 128(2^8)个字符。如A⽤65表示﹐存在计算机中就是01 01(65)﹐为了书写⽅便﹐我们⼀般记作 0×41(16进制),97则表示⼩写的a,存在计算机中就是01 01 (97)﹐记作0×61。?⽤63表示,记作 0×3F。
- 7.英语国家的⼤⼩写字⺟加起来才52个字符﹐再加上数字﹐符号和⼀些特殊字符﹐已经⾜够使⽤。所 以ASCI刚开始⾮常流⾏(谁叫计算机不是咱中国发明的… )
- 8.随着计算机的普及﹐当⾮英语系的国家开始使⽤时﹐ASCI已经明显不能满⾜了(总不成天天使⽤xiao sheng来表示”⼩⽣”吧),所以这些国家(地区)就开始制订⾃⼰的标准。
- 9. 中国⼤陆制订了简体汉字的字符集(GB2312)。和英语国家不同﹐我们的汉字远远不⽌128个﹐所以 ⼀个byte肯定不能表示完﹐那就多加个byte, 16位(6536)总可以了吧。不过这样虽解决了位数不够的 问题﹐但是原来的英⽂⽂件怎么办?总不成⼜全部拿出来改成双字节吧。幸好﹐居然发现原来的 ASCI 的第⼀位居然是0﹐那我们把第1位改成1不就OK了吗?以后凡看到0开头的就读1个字节﹐1开头的就读2 个字节。(⽽且128*128表示所有的简体字也⾜够了)
- 10.因此在GB2312标准中,”⼩”的序号是0xD0A1,表示成 101 0 101 01,⽽A还是表示成01 01, 这就是为什么简体操作系统读ASCI⽂件不会乱码﹐⽽反之则不然的原因。
