我们要讨论的主要问题是，为什么上⾯注解处要与OxF进⾏与运算⽽不是其他值呢？ 因为OxF的16进制数为 f (即8个f)。按与运算的法则，

先来看⼆进制的与运算，如：-1 & 1 ＝ 1

- -1（负1）的⼆进制编码为： 1 1 1 1 即⼀个32位的字符串，前⾯⼀ 位是1表⽰负数 1（正1） 的⼆进制编码为： 0 0 0 01 即，只有最后⼀位是 1，其他部分全部为0 按&（与运算）的法则结果： 0 0 0 01 即，只有当两个都为1 时才为1，所以最后的结果为：1(正1)


则可以知道为什么要与0xF进⾏与运算，因为OxF的16进⾏为 ： 0F。任意数与OxF进⾏与 运算都是取16进制的后两位

运算⽰例如下：

- -127(负数127)的16进制为： F81 0xF的16进制为： 0F 则&（与）运算是结果为： 081 所以：Integer.toHexString(-127 &0xF) 的结果为：81。


另外，其中很多计算，都使⽤0x这样的16进制进⾏运⾏： 如 0xF的⼆进制为 1 ,即四个1。

0xF的⼆进制为 1 1 ,即8个1的⼆进制形式 每多⼀个F就是多⼀个4位的 1。 最多8个F。

- 12、深⼊ThreadLocal的内部机制


早在JDK 1.2的版本中就提供java.lang.ThreadLocal，ThreadLocal为解决多线程程序的并发问题提供了 ⼀种新的思路。使⽤这个⼯具类可以很简洁地编写出优美的多线程程序。ThreadLocal并不是⼀个 Thread，⽽是Thread的局部变量。当使⽤ThreadLocal维护变量时，ThreadLocal为每个使⽤该变量的 线程提供独⽴的变量副本。 ThreadLocal的接⼜⽅法： void set(Object value)：设置当前线程的线程局部变量的值。 public Object get()：该⽅法返回当前线程所对应的线程局部变量。 public void remove()：将当前线程局部变量的值删除，⽬的是为了减少内存的占⽤，该⽅法是JDK5.0 新增的⽅法。 需要指出的是，当线程结束后，对应该线程的局部变量将⾃动被垃圾回收， 所以显式调⽤该⽅法清除线程的局部变量并不是必须的操作，但它可以加快内存回收的速度。 protected Object initialValue()：返回该线程局部变量的初始值，该⽅法是⼀个protected的⽅法，显 然是为了让⼦类覆盖⽽设计的。 这个⽅法是⼀个延迟调⽤⽅法，在线程第1次调⽤get()或set(Object)时才执⾏， 并且仅执⾏1次。ThreadLocal中的缺省实现直接返回⼀个nul。 在JDK5.0中，ThreadLocal已经⽀持泛型，该类的类名已经变为ThreadLocal<T>。 ThreadLocal是如何做到为每⼀个线程维护变量的副本的呢？其实实现的思路很简单：在ThreadLocal 类中有⼀个Map，⽤于存储每⼀个线程的变量副本 模拟ThreadLocal代码清单：

- 12.2、对象的引用


ThreadLocal可以很好的维护线程局部的对象，那么它是如何做到及时将对象从内存中回收的呢？ 遍观ThreadLocal的源代码可知，ThreadLocal是通过弱引⽤实现对象可以在内存被及时清回收

的，以下是从ThreadLocal内部类Entry的源代码，可见Entry内部是WeakReferences（弱引⽤）的⼦ 类，即⼀个弱引⽤⽽已：

static class Entry extends WeakReference<ThreadLocal> { /** The value associated with this ThreadLocal. */ Object value; Entry(ThreadLocal k, Object v) {

super(k); value = v;

} }

从JDK1.2版本开始，把对象的引⽤分为四种级别，从⽽使程序能更加灵活的控制对象的⽣命周期。这 四种级别由⾼到低依次为：强引⽤、软引⽤、弱引⽤和虚引⽤。

- 1．强引⽤ 本章前⽂介绍的引⽤实际上都是强引⽤，这是使⽤最普遍的引⽤。如果⼀个对象具有强引⽤，那就类 似于必不可少的⽣活⽤品，垃圾回收器绝不会回收它。当内存空间不⾜，Java虚拟机宁愿抛出 OutOfMemoryEror错误，使程序异常终⽌，也不会靠随意回收具有强引⽤的对象来解决内存不⾜问 题。

- 2．软引⽤（SoftReference） 如果⼀个对象只具有软引⽤，那就类似于可有可物的⽣活⽤品。如果内存空间⾜够，垃圾回收器就不 会回收它，如果内存空间不⾜了，就会回收这些对象的内存。只要垃圾回收器没有回收它，该对象就 可以被程序使⽤。软引⽤可⽤来实现内存敏感的⾼速缓存。软引⽤可以和⼀个引⽤队列 （ReferenceQueue）联合使⽤，如果软引⽤所引⽤的对象被垃圾回收，Java虚拟机就会把这个软引⽤ 加⼊到与之关联的引⽤队列中。

- 3．弱引⽤（WeakReference） 如果⼀个对象只具有弱引⽤，那就类似于可有可物的⽣活⽤品。弱引⽤与软引⽤的区别在于：只具有 弱引⽤的对象拥有更短暂的⽣命周期。在垃圾回收器线程扫描它所管辖的内存区域的过程中，⼀旦发 现了只具有弱引⽤的对象，不管当前内存空间⾜够与否，都会回收它的内存。不过，由于垃圾回收器 是⼀个优先级很低的线程，因此不⼀定会很快发现那些只具有弱引⽤的对象。弱引⽤可以和⼀个引⽤ 队列（ReferenceQueue）联合使⽤，如果弱引⽤所引⽤的对象被垃圾回收，Java虚拟机就会把这个弱 引⽤加⼊到与之关联的引⽤队列中。

- 4．虚引⽤（PhantomReference） "虚引⽤"顾名思义，就是形同虚设，与其他⼏种引⽤都不同，虚引⽤并不会决定对象的⽣命周期。如 果⼀个对象仅持有虚引⽤，那么它就和没有任何引⽤⼀样，在任何时候都可能被垃圾回收。虚引⽤主 要⽤来跟踪对象被垃圾回收的活动。虚引⽤与软引⽤和弱引⽤的⼀个区别在于：虚引⽤必须和引⽤队 列（ReferenceQueue）联合使⽤。当垃 圾回收器准备回收⼀个对象时，如果发现它还有虚引⽤，就会 在回收对象的内存之前，把这个虚引⽤加⼊到与之关联的引⽤队列中。程序可以通过判断引⽤队列中 是否已经加⼊了虚引⽤，来了解被引⽤的对象是否将要被垃圾回收。程序如果发现某个虚引⽤已经被 加⼊到引⽤队列，那么就可以在所引⽤的对象的内存被回收之前采取必要的⾏动。 为弱引⽤使⽤较多：
