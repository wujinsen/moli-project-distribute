下⾯是使⽤Serial/Serial Old收集器下（ParNew/Serial Old收集器组合的规则也基本⼀致）的内存分配 和回收的策略

对象优先在Eden分配

- 1、⼤多数情况下，对象在新⽣代Eden区中分配。当Eden区没有⾜够空间进⾏分配时，虚拟机将发起 ⼀次MinorGC。
- 2、执⾏GC后，将存活的对象分配到Survivor空间
- 3、⽆法放到Survivor空间的对象，分配到⽼年代
- 4、分配到Survivor的对象，经过15次Minor GC后，进⼊⽼年代


新⽣代GC（Minor GC）：指发⽣在新⽣代的垃圾收集动作，因为Java对象⼤多都具备朝⽣夕灭的 特性，所以 Minor GC⾮常频繁，⼀般回收速度也⽐较快。

⽼年代GC（Major GC/Ful GC）：指发⽣在⽼年代的GC，出现了Major GC，经常会伴随⾄少⼀ 次的Minor

GC（但⾮绝对的，在Paralel Scavenge收集器的收集策略⾥就有直接进⾏Major GC的策略选择过 程）。Major GC 的速度⼀般会⽐Minor GC慢10倍以上。

⼤对象直接进⼊⽼年代

- 1、⼤对象：需要⼤量连续内存空间的Java对象，最典型的⼤对象就是那种很⻓的字符串以及数组
- 2、虚拟机提供了⼀个-X：PretenureSizeThreshold参数，令⼤于这个设置值的对象直接在⽼年代分 配


⻓期存活的对象将进⼊⽼年代

- 1、虚拟机给每个对象定义了⼀个对象年龄（Age）计数器
- 2、如果对象在Eden出⽣并经过第⼀次Minor GC后仍然存活，并且能被Survivor容纳的话，将被移动到 Survivor空间中，并且对象年龄设为1。
- 3、对象在Survivor区中每“熬过”⼀次Minor GC，年龄就增加1岁
- 4、当它的年龄增加到⼀定程度（默认为15岁），就将会被晋升到⽼年代中
- 5、对象晋升⽼年代的年龄阈值，可以通过参数-X：MaxTenuringThreshold设置


动态对象年龄判定 1、为了能更好地适应不同程序的内存状况，虚拟机并不是永远地要求对象的年龄必须达到了 MaxTenuringThreshold才能晋升⽼年代2、如果在Survivor空间中相同年龄所有对象⼤⼩的总和⼤于 Survivor空间的⼀半，年龄⼤于或等于该年龄的对象就可以直接进⼊⽼年代，⽆须等到 MaxTenuringThreshold中要求的年龄。

空间分配担保

- 1、在发⽣Minor GC之前，虚拟机会先检查⽼年代最⼤可⽤的连续空间是否⼤于新⽣代所有对象总空间
- 2、如果这个条件成⽴，那么Minor GC可以确保是安全的
- 3、如果不成⽴，则虚拟机会查看HandlePromotionFailure设置值是否允许担保失败4、如果允许，那 么会继续检查⽼年代最⼤可⽤的连续空间是否⼤于历次晋升到⽼年代对象的平均⼤⼩


- 5、如果⼤于，将尝试着进⾏⼀次Minor GC，尽管这次Minor GC是有⻛险的
- 6、如果⼩于，或者HandlePromotionFailure设置不允许冒险，那这时也要改为进⾏⼀次Ful GC
