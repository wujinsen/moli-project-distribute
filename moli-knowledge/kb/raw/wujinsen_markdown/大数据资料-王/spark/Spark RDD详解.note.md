- 1、RD是什么 RD：Spark的核⼼概念是RD (resilientdistributed dataset)，指的是⼀个只读的，可分区的分布式数 据集，这个数据集的全部或部分可以缓存在内存中，在多次计算间重⽤。


为什么会产⽣RD？

- （1）传统的MapReduce虽然具有⾃动容错、平衡负载和可拓展性的优点，但是其最⼤缺点是采⽤⾮循 环式的数据流模型，使得在迭代计算式要进⾏⼤量的磁盘IO操作。RD正是解决这⼀缺点的抽象⽅法
- （2）RD的具体描述RD（弹性数据集）是Spark提供的最重要的抽象的概念，它是⼀种有容错机制 的特殊集合，可以分布在集群的节点上，以函数式编操作集合的⽅式，进⾏各种并⾏操作。可以将 RD理解为⼀个具有容错机制的特殊集合，它提供了⼀种只读、只能有已存在的RD变换⽽来的共享 内存，然后将所有数据都加载到内存中，⽅便进⾏多次重⽤。a.他是分布式的，可以分布在多台机器 上，进⾏计算。b.他是弹性的，计算过程中内错不够时它会和磁盘进⾏数据交换。c.这些限制可以极⼤ 的降低⾃动容错开销d.实质是⼀种更为通⽤的迭代并⾏计算框架，⽤户可以显示的控制计算的中间结 果，然后将其⾃由运⽤于之后的计算。
- （3）RD的容错机制实现分布式数据集容错⽅法有两种：数据检查点和记录更新RD采⽤记录更新的 ⽅式：记录所有更新点的成本很⾼。所以，RD只⽀持粗颗粒变换，即只记录单个块上执⾏的单个操 作，然后创建某个RD的变换序列（⾎统）存储下来；变换序列指，每个RD都包含了他是如何由其 他RD变换过来的以及如何重建某⼀块数据的信息。因此RD的容错机制⼜称“⾎统”容错。 要实现这 种“⾎统”容错机制，最⼤的难题就是如何表达⽗RD和⼦RD之间的依赖关系。实际上依赖关系可以 分两种，窄依赖和宽依赖：窄依赖：⼦RD中的每个数据块只依赖于⽗RD中对应的有限个固定的数 据块；宽依赖：⼦RD中的⼀个数据块可以依赖于⽗RD中的所有数据块。例如：map变换，⼦RD 中的数据块只依赖于⽗RD中对应的⼀个数据块；groupByKey变换，⼦RD中的数据块会依赖于多有 ⽗RD中的数据块，因为⼀个key可能错在于⽗RD的任何⼀个数据块中 将依赖关系分类的两个特 性：第⼀，窄依赖可以在某个计算节点上直接通过计算⽗RD的某块数据计算得到⼦RD对应的某块 数据；宽依赖则要等到⽗RD所有数据都计算完成之后，并且⽗RD的计算结果进⾏hash并传到对应 节点上之后才能计算⼦RD。第⼆，数据丢失时，对于窄依赖只需要重新计算丢失的那⼀块数据来恢 复；对于宽依赖则要将祖先RD中的所有数据块全部重新计算来恢复。所以在⻓“⾎统”链特别是有宽 依赖的时候，需要在适当的时机设置数据检查点。也是这两个特性要求对于不同依赖关系要采取不同 的任务调度机制和容错恢复机制。


- （4）RD内部的设计每个RD都需要包含以下四个部分：a.源数据分割后的数据块，源代码中的 splits变量b.关于“⾎统”的信息，源码中的dependencies变量c.⼀个计算函数（该RD如何通过⽗RD 计算得到），源码中的iterator(split)和compute函数d.⼀些关于如何分块和数据存放位置的元信息，如 源码中的partitioner和preferedLocations例如：a.⼀个从分布式⽂件系统中的⽂件得到的RD具有的 数据块通过切分各个⽂件得到的，它是没有⽗RD的，它的计算函数知识读取⽂件的每⼀⾏并作为⼀ 个元素返回给RD；b.对与⼀个通过map函数得到的RD，它会具有和⽗RD相同的数据块，它的计 算函数式对每个⽗RD中的元素所执⾏的⼀个函数


- 2、RD在Spark中的地位及作⽤

- （1）为什么会有Spark？因为传统的并⾏计算模型⽆法有效的解决迭代计算（iterative）和交互式计算 （interactive）；⽽Spark的使命便是解决这两个问题，这也是他存在的价值和理由。
- （2）Spark如何解决迭代计算？其主要实现思想就是RD，把所有计算的数据保存在分布式的内存 中。迭代计算通常情况下都是对同⼀个数据集做反复的迭代计算，数据在内存中将⼤⼤提升IO操作。 这也是Spark涉及的核⼼：内存计算。
- （3）Spark如何实现交互式计算？因为Spark是⽤scala语⾔实现的，Spark和scala能够紧密的集成， 所以Spark可以完美的运⽤scala的解释器，使得其中的scala可以向操作本地集合对象⼀样轻松操作分 布式数据集。
- （4）Spark和RD的关系？可以理解为：RD是⼀种具有容错性基于内存的集群计算抽象⽅法， Spark则是这个抽象⽅法的实现。
