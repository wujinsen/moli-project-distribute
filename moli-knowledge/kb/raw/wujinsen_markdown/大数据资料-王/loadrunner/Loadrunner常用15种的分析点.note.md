Vusers：提供了⽣产负载的虚拟⽤户运⾏状态的相关信息，可以帮助我们了解负载⽣成的结果。 Rendezvous（负载过程中集合点下的虚拟⽤户）：当设置集合点后会⽣成相关数据，反映了随着 时间的推移各个时间点上并发⽤户的数⽬，⽅便我们了解并发⽤户的变化情况。 Erors（错误统计）：通过错误信息可以了解错误产⽣的时间和错误类型，⽅便定位产⽣错误的原 因。 Erors per Second（每秒错误）：了解在每个时间点上错误产⽣的数⽬，数值越⼩越好。通过统 计数据可以了解错误随负载的变化情况，定为何时系统在负载下开始不稳定甚⾄出错。 Average Transaction Response Time（平均事务响应时间）：反映随着时间的变化事务响应时间 的变化情况，时间越⼩说明处理的速度越快。如果和⽤户负载⽣成图合并，就可以发现⽤户负载 增加对系统事务响应时间的影响规律。 Transactions per Second（每秒事务）：TPS吞吐量，反映了系统在同⼀时间内能处理事务的最 ⼤能⼒，这个数据越⾼，说明系统处理能⼒越强。 Transactions Sumary（事务概要说明） 统计事物的Pas数和Fail数，了解负载的事务完成情 况。通过的事务数越多，说明系统的处理能⼒越强；失败的事务数越⼩说明系统越可靠。 Transaction performance Sumary(事务性能概要)：事务的平均时间、最⼤时间、最⼩时间柱状 图，⽅便分析事务响应时间的情况。柱状图的落差越⼩说明响应时间的波动⼩，如果落差很⼤， 说明系统不够稳定。 Transaction Response Time Under Load（⽤户负载下事务响应时间）：负载⽤户增⻓的过程中 响应时间的变化情况，该图的线条越平稳，说明系统越稳定。 Transactions Response time(事务响应时间百分⽐)：不同百分⽐下的事务响应时间范围，可以了 解有多少⽐例的事物发⽣在某个时间内，也可以发现响应时间的分布规律，数据越平稳说明响应 时间变化越⼩。 Transaction Response Time（各时间段上的事务数）：每个时间段上的事务个数，响应时间较⼩ 的分类下的是⽆数越多越好。 Hits per Second（每秒点击）：当前负载重对系统所产⽣的点击量记录，每⼀次点击相当于对服 务器发出了⼀次请求，数据越⼤越好。 Throughput（吞吐量）：系统负载下所使⽤的带宽，该数据越⼩说明系统的带宽依赖就越⼩，通 过这个数据可以确定是不是⽹络出现了瓶颈。 HTP Responses per Second（每秒HTP响应）：每秒服务器返回各种状态的数⽬，⼀般和每秒 点击量相同。点击量是客户端发出的请求数，⽽HTP响应数是服务器返回的响应数。如果服务器 的响应数⼩于点击量，那么说明服务器⽆法应答超出负载的连接请求。 Conections per Second（每秒连接）：统计终端的连接和新建的连接数，⽅便了解每秒对服务 器产⽣连接的数量。同时连接数越多，说明服务器的连接池越⼤，当连接数随着负载上升⽽停⽌ 时，说明系统的连接池已满，通常这时候服务器会返回504错误。需要修改服务器的最⼤连接来解 决该问题。
