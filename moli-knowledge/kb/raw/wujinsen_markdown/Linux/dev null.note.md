默认情况下，总是有三个⽂件处于打开状态，标准输⼊(键盘输⼊)、标准输出（输出到屏幕）、标准错 误（也是输出到屏幕），它们分别对应的⽂件描述符是0，1，2 。那么我们来看看下⾯的⼏种重定向 ⽅法的区别： >/dev/null 2>&1 // 实际上，应该等同于这样： 1>/dev/null 2>/dev/null ，默认情况下就是1，标准输出，所以⼀般都省 略。 ⽽&符号，后⾯接的是必须的⽂件描述符。不能写成2>1，这样就成了标准错误重定向到⽂件名为 1的⽂件中了，⽽不是重定向标准错误到标准输出中。所以这⾥就是：标准输出重定向到了/dev/null， ⽽标准错误⼜重定向到了标准输出，所以就成了标准输出和标准错误都重定向到了/dev/null

2>&1 >/dev/null // 咋⼀看，这个跟上⾯那个有啥区别呢，不也是标准错误重定向到标准输出，⽽标准输出重定向 到/dev/null么？ 最后不应该都重定向/dev/null么？ 我是这么理解的！⼀条指令同⼀时刻要么产⽣标准 错误，要么产⽣标准输出。 当产出标准错误的时候，因这个标准错误重定向到了标准输出，⽽标准输 出是输出到屏幕。这个时候标准输出还没有被重定向到/dev/null，于是在屏幕上打印了。当产⽣标准输 出时，那么它就不是标准错误，2>&1⽆效，于是标准输出重定向dev/null，不打印到屏幕。所以最终结 果将是：标准错误打印到屏幕，⽽标准输出不打印到屏幕。
