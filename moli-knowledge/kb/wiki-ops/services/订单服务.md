# 订单服务（order-server）

订单业务服务。目前**真实亮点是秒杀子系统**（面向高并发演示与压测），通用订单域仅占位。

| 项 | 值 |
|----|----|
| 服务名 | `order-server` |
| HTTP 端口 | 8087 |
| Dubbo 端口 | 20882（Consumer，订阅 user-center-server） |
| 网关路由 | `/OrderServer/**` → StripPrefix=1 |

## 完成度

| 部分 | 状态 | 说明 |
|------|------|------|
| 通用订单 | 🔴 骨架 | `OrderController` 仅一个返回当前登录用户的探针接口 `/order/ccc`，无订单表/支付/状态流转 |
| 秒杀子系统 | 🟡 示例/压测级 | Redis+Lua 扣减 + 异步落库热路径完整，设计见 [[秒杀设计]] |

## 秒杀接口（经网关 `/OrderServer/seckill/...`）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/seckill/ping` | 连通性 |
| GET | `/seckill/activity/{activityId}` | 查库存（优先 Redis） |
| POST | `/seckill/order` | 秒杀下单（核心，200成功/409售罄/429重复） |
| GET | `/seckill/metrics` | Redis 计数指标 |
| POST | `/seckill/admin/init` | 初始化活动（仅 `load-test-mode=true`） |

## 依赖关系

- 通过 **Dubbo** 调 [[用户中心]] 做账号校验/拉权限，本地不登录（见 [[认证与会话机制]]）。
- 对外经 [[网关]] 的 `/OrderServer/**` 暴露。
- 压测脚本（k6/Gatling/wrk）深度绑定本服务秒杀接口，见 `load-test/`。
