# 压测报告解读指南

> 怎么压 [[秒杀压测指南]]；看板 [[压测监控与prometheus]]。

## 1. k6 核心指标

| 指标 | 含义 | 健康参考 |
|------|------|----------|
| `http_req_duration` p95 | 95% 请求延迟 | 业务定 SLA（如 <500ms） |
| `http_req_failed` | 失败率 | 秒杀允许部分业务失败，系统错误应 ≈0 |
| `iterations/s` | 吞吐 | 对比阶梯是否线性 |
| `vus` | 虚拟用户 | 与目标 QPS 对照 |

## 2. 分层看瓶颈

```
k6 → Gateway → order/user-center → Redis/MySQL
```

| 症状 | 方向 |
|------|------|
| p95 陡升、错误 401 | Redis Session [[茉莉登录与鉴权故障根因汇总]] |
| p95 升、Dubbo 超时 | 线程池/DB [[rpc-超时重试与链路]] |
| Redis CPU 100% | 热 key [[redis-热key与大key治理]] |
| MySQL 连接满 | Druid [[druid连接池与监控]] |
| Gateway CPU | Netty 线程 [[netty-reactor与线程模型]] |

## 3. Grafana 联动

- JVM 堆/GC、Druid active/waiting
- 与 k6 时间轴对齐看 **同一时刻**

## 4. 报告模板（checklist）

- [ ] 场景：vus 阶梯、duration、目标 API
- [ ] 业务：成功下单数 vs 库存
- [ ] 系统：p95/p99、错误率、资源峰值
- [ ] 结论：瓶颈组件 + 下一步优化项
