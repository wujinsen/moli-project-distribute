# 登录与鉴权指南

面向「我怎么登录、怎么带 token 调接口」的操作指导。机制原理见 [[认证与会话机制]]。

## 1. 登录拿 token

所有登录都走 [[网关]]，只有 [[用户中心]] 能登录：

```bash
curl -X POST http://localhost:21000/UserCenter/login \
  -H "Content-Type: application/json" \
  -d '{"userName":"admin","password":"你的密码"}'
```

返回 `LoginVo`，关键字段：

```json
{
  "code": 200,
  "data": {
    "token": "login_token_xxxxxxxx",
    "user": { ... },
    "menuVoList": [ ... ],
    "permissions": ["system:user:list", "..."]
  }
}
```

> `token` 就是 Shiro Session ID，不是 JWT。

## 2. 带 token 调任意接口

把 token 放进 **`Authorization` 请求头**（不是 Cookie），调哪个服务都一样：

```bash
# 调用户中心
curl http://localhost:21000/UserCenter/user/list \
  -H "Authorization: login_token_xxxxxxxx"

# 调订单服务（同一个 token，跨服务通用）
curl http://localhost:21000/OrderServer/order/ccc \
  -H "Authorization: login_token_xxxxxxxx"
```

跨服务能通用，是因为所有服务共享同一个 Redis 会话（见 [[认证与会话机制]]）。

## 3. 常见返回码

| code | 含义 | 处理 |
|------|------|------|
| 200 | 成功 | — |
| 10006 | token 无效/未登录 | 重新登录 |
| 10009 | 无权限（缺 perms） | 找管理员授权，见 [[权限管理操作指南]] |

## 4. 登出 / 补拉权限

```bash
curl -X POST http://localhost:21000/UserCenter/logout -H "Authorization: login_token_xxx"
curl http://localhost:21000/UserCenter/auth/capabilities -H "Authorization: login_token_xxx"
```

## 常见问题

- **登录成功但调业务服务报未登录** → 多半是业务服务和用户中心**没连同一个 Redis**（含 database），见 [[本地启动指南]]。
- **接口返回 10009** → 账号缺该接口的 `perms`，权限模型见 [[rbac-权限模型]]。
- **压测场景** → 用 `POST /UserCenter/loadtest/login`（loadtest profile，不写日志/不查菜单）。
