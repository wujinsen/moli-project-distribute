# 高并发券系统实战

> 通用架构文（字节跳动技术团队 CSDN 稿提炼）。**enterprise-kb** 技术参考；与具体项目秒杀实现对照时见各项目手册，勿混为单一项目真相源。

## 1. 需求拆解

| 能力 | 说明 |
|------|------|
| 券模板 | 批次、有效期、库存 |
| 发券 | 用户领券记录、幂等 |
| 查询 | 模板/记录条件查询 |
| 过期 | 状态推进 |

## 2. 技术选型（原文栈）

| 层 | 选型 | 理由 |
|----|------|------|
| 存储 | MySQL | 结构化、条件查询 |
| 缓存 | Redis | 模板缓存、库存扣减 |
| MQ | RocketMQ | 延时消息处理过期 |
| RPC | 各语言 RPC 框架 | 上游同步调用 |

Java 技术栈可类比：**Dubbo + MySQL + Redis + RocketMQ**（见 [[middleware/消息队列]]）。

## 3. 核心流程

**发券**：参数校验 → **幂等**（防重试多发）→ **库存扣减**（Redis）。

**过期**：RocketMQ 延时消息；有效期超过 MQ 最大延时则**循环投递**直到过期。

幂等实践见 [[middleware/接口幂等性实践]]；缓存更新见 [[cache/cache-aside与缓存更新模式]]。

## 4. 大流量三板斧

### 4.1 存储瓶颈

- MySQL 单库写 ~4k QPS 量级（压测值，环境相关）
- **读写分离** + **分库分表**（按 `user_id` 分片领券记录）
- Redis 单分片写 ~2w、读 ~10w（原文估算）

详见 [[database/sharding-分库分表入门]]。

### 4.2 热点库存

单券模板库存 key 打满单 Redis 分片 → **拆子库存 key**，扣减时**随机不重复轮询**子库存；库存将尽时跳过已耗尽分片。

读多写少场景可用 key 备份打散；**写多读少发券**更适合拆 key。

### 4.3 模板缓存超时

Redis 超时万分之几不可避免 → **本地二级缓存** + 定时刷新；刷 Redis 加**分布式锁**防多实例同时写。

## 5. 服务治理

| 手段 | 要点 |
|------|------|
| 超时 | RPC 超时略大于 P99（如内部 10ms → 超时 50ms） |
| 监控 | Grafana + 告警 |
| 限流 | 保护下游券服务 [[middleware/sentinel-限流与熔断]] |
| 压测 | 先单实例、MySQL 主写、Redis 分片瓶颈，再全链路 |

原文压测：**13w QPS 发券，成功率 99.9%+**。
