# 跨域与前后端分离

前后端分离后，浏览器从 `http://localhost:9528` 访问 `http://localhost:21000` 属于**跨域**（协议/域名/端口任一不同）。Postman 无同源策略，故「Postman 正常、浏览器失败」多为 CORS 或 Cookie 域问题。

## 1. 同源策略速记

「源」= `protocol + host + port`。子域、端口、协议不同均跨域；**前端无法绕过**协议/端口级跨域，需服务端或代理配合。

## 3. 其它方案（了解即可）

| 方案 | 适用 |
|------|------|
| JSONP | 仅 GET，已过时 |
| document.domain + iframe | 同主域子域 |
| WebSocket | 握手前仍可能遇 CORS |
| 后端 `@CrossOrigin` | 单体或小服务；微服务优先网关统一 |

## 4. 三种 POST 与 Content-Type

联调登录/表单时注意与后端 `@RequestMapping(consumes=...)` 一致：

| 方式 | 前端 | 后端 |
|------|------|------|
| GET | `params: { username, password }` | 方法参数绑定 |
| POST form | `URLSearchParams` + `application/x-www-form-urlencoded` | `consumes = APPLICATION_FORM_URLENCODED` |
| POST JSON | `data: { ... }` | `@RequestBody` + `APPLICATION_JSON` |

登录以项目实际 Controller 为准，调试见。

## 5. 排查清单

1. 浏览器 Network 看 OPTIONS 预检是否 200。
2. 响应头是否含 `Access-Control-Allow-Origin`（credentials 时不能 `*` 与 credentials 乱配）。
3. 是否网关 + 业务**双重** CORS。
4. token 走 Header 而非跨域 Cookie 时，确认 `Authorization` 在 allowed-headers 内。
