# 消息队列

> 选型对比 [[middleware/kafka-与-mq选型]]；秒杀现状 ；入口限流 [[middleware/sentinel-限流与熔断]]。

消息队列（MQ）是**异步通信中间件**，在高并发里常与缓存、限流并称「保护系统的三件套」。

## 1. 四大价值

| 价值 | 说明 |
|------|------|
| **解耦** | 上下游只认消息，不认实现 |
| **异步** | 调用方快速返回 |
| **削峰** | 秒杀流量写入 MQ，消费者按能力拉取 |
| **广播** | 一条消息多订阅者 |

最终一致性、日志采集、事件驱动是常见延伸场景。

## 2. 核心概念

| 概念 | Kafka | RocketMQ | RabbitMQ |
|------|-------|----------|----------|
| 消息单位 | Message | Message | Message |
| 队列逻辑 | Topic-Partition | Topic-Queue | Queue/Exchange |
| 消费模式 | Pull 为主 | Pull/Push | Push 为主 |
| 顺序 | 分区内有序 | 队列有序 | 单队列有序 |

## 3. 与 RPC 边界

| | Dubbo/HTTP | MQ |
|---|------------|-----|
| 语义 | 同步请求-响应 | 异步、可堆积 |
| 耦合 | 强（需在线） | 弱（消费者可滞后） |
| 适用 | 实时查询、鉴权 | 订单异步、日志、通知 |

服务间以 **Dubbo + Gateway HTTP** 为主（）。

## 5. 秒杀 + MQ 典型架构

```
POST /seckill → Redis Lua 扣库存 → 发 MQ(订单消息) → 消费者落 MySQL
```

相对现状 Redis 队列的优点：

- 持久化与副本（Kafka/RocketMQ）
- 消费失败重试、死信队列
- 堆积不占用 Redis 内存

配合 [[middleware/sentinel-限流与熔断]] 保护入口，MQ 缓冲写库峰值。

Kafka / RocketMQ / RabbitMQ 对比见 [[middleware/kafka-与-mq选型]]。高并发发券架构见 [[middleware/高并发券系统实战]]。
