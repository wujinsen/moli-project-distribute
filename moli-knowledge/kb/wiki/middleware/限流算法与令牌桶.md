# 限流算法与令牌桶

> Sentinel 如何落地 [[middleware/sentinel-限流与熔断]]；秒杀入口 ；连接池也是一种限流 [[database/druid连接池与监控]]。

限流：**对并发访问或时间窗内请求限速**，超限可拒绝、排队或降级，目标是**有损服务而不是不服务**。

## 1. 常见限流维度

| 维度 | 示例 |
|------|------|
| 总并发/连接数 | Tomcat maxThreads、MySQL max_connections、**Druid max-active** |
| 瞬时并发 | nginx limit_conn |
| 时间窗平均速率 | QPS、Guava RateLimiter、Sentinel QPS 规则 |
| 远程调用/MQ | Dubbo TpsLimitFilter、消费速率 |

## 2. 三大算法

### 计数器

固定时间段内请求数超阀值则拒绝。实现简单，**边界可能突刺**（如 1 秒内前后各打满）。

适合：线程池最大任务数、秒杀总并发上限。

### 漏桶（Leaky Bucket）

以**固定速率**流出请求；流入任意速率，桶满则溢出丢弃。输出平滑，**不允许突发**。

### 令牌桶（Token Bucket）

以固定速率向桶加令牌；请求消耗令牌，不足则限流。**允许一定程度突发**（桶内有令牌即可处理）。

| 对比 | 令牌桶 | 漏桶 |
|------|--------|------|
| 突发 | 允许（桶容量内） | 平滑流出 |
| 典型实现 | Guava RateLimiter、Sentinel | 流量整形 |

> 相同参数下两种算法限流效果可等价，选型看是否需要允许突发。

## 3. Guava RateLimiter 要点

```java
RateLimiter limiter = RateLimiter.create(5); // 5 令牌/秒
limiter.acquire(); // 阻塞直到拿到令牌
limiter.tryAcquire(); // 非阻塞
```

- `SmoothBursty`：允许突发（桶容量 ≈ 速率 × maxBurstSeconds）
- `SmoothWarmingUp`：冷启动渐近目标速率（预热）

单机限流够用；**多实例需分布式方案**。

## 4. 分布式限流：Redis + Lua

用 `INCR` + `EXPIRE` 做秒级计数，Lua 保证原子性：

```lua
local current = tonumber(redis.call('get', key) or "0")
if current + 1 > limit then return 0
else redis.call('INCRBY', key, 1); redis.call('expire', key, 2); return 1 end
```

秒杀库存扣减已是 Redis Lua（）；**接口 QPS 限流**可同类思路或交 Sentinel 统一管。

注意：时钟依赖应用侧传秒级 key，极端时钟漂移会有误差。

## 5. 应用级简易限流

接口总并发：`AtomicLong` 进出计数（适合抢购「排队/售罄」语义）。

时间窗：`LoadingCache<秒, AtomicLong>` + `expireAfterWrite(2s)` 做每秒计数。

## 6. 选型建议

| 场景 | 建议 |
|------|------|
| 网关统一入口 | Sentinel / nginx limit_req |
| 单 JVM 接口 | RateLimiter |
| 多节点一致 QPS | Sentinel 集群 / Redis Lua |
| 稀缺资源总数 | 连接池、线程池、计数器 |
| 秒杀 | Redis 业务 Lua + **规划** Gateway Sentinel |

不要过度限流导致正常流量异常；先监控再设阀值（[[middleware/压测监控与prometheus]]）。
