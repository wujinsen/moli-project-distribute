# 字段级数据权限设计

> 菜单/动作 RBAC 见 [[rbac-权限模型]]；操作入口 [[权限管理操作指南]]。茉莉**当前未实现**字段级权限，本文为扩展设计参考（与 BI/报表场景相关）。

## 业务场景

统计类系统表多、字段多，需控制「谁能看哪些列」，如 `day_amount` 仅管理员可见，`month_amount` 仅财务角色可见。

## 三种方案（由简到繁）

| 方案 | 模型 | 优点 | 缺点 |
|------|------|------|------|
| **一** | 用户-表-字段 | 实现简单 | 每人每表每字段配置，繁琐 |
| **二** | 角色-表-字段 + 用户覆盖 | 角色批量授权 | 单表粒度 |
| **三** | 数据类型 + 角色/用户 | 跨表按「类型」控字段 | 实现复杂 |

对外接口：统一以 **表名 → 字段** 树形分配。

## 实现难点

1. **表结构变更** → 权限映射需同步维护  
2. **计算字段**（非 DB 列）权限难绑 SQL  
3. **多表 JOIN** 与字段权限冲突 → 常改为应用层组装，放弃大 JOIN  

## 技术路线（原文思路）

- Spring `AbstractAutoProxyCreator` + `MethodInterceptor` 在返回前过滤 DTO 字段  
- 或 MyBatis 拦截器改 SELECT 列（动态 SQL）  
- JSON 序列化层 `@JsonView` / 自定义 Filter

## 与茉莉 RBAC 的关系

现有 [[rbac-权限模型]] 管 **菜单 + 动作**（接口级 `@RequiresPermissions`），**不管列级**。若 [[bi服务]] 做报表：

- 短期：按角色分报表/接口，接口内写死可见指标  
- 长期：方案二 + 元数据表，与 `sys_role` 关联

## 面试/评审一句话

> 字段级权限是 RBAC 之上的细粒度层；优先角色映射，表结构变更要有同步机制；多表场景宜应用层聚合。
