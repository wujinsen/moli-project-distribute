# 分布式事务

> CAP/BASE [[分布式理论基础]]；茉莉以**单库 + 最终一致**为主，未全面上 Seata。

## 1. 问题

跨服务/跨库操作无法用一个本地 `@Transactional` 覆盖，需协调 **提交或回滚**。

## 2. 方案谱系

| 方案 | 一致性 | 复杂度 | 适用 |
|------|--------|--------|------|
| **2PC/XA** | 强 | 高、阻塞 | 银行级少 |
| **TCC** | 较强 | 业务侵入 Try/Confirm/Cancel | 核心账务 |
| **本地消息表** | 最终 | 中 | 订单+积分 |
| **MQ 事务消息** | 最终 | 中 | RocketMQ 半消息 [[rocketmq-事务消息实践]] |
| **Saga** | 最终 | 编排/ choreography | 长流程 |

## 3. 茉莉实践取向

- 单服务单库：Spring `@Transactional` [[spring-声明式事务]]
- 跨服务：Dubbo 同步 + **幂等** + 对账，而非强一致分布式事务
- 秒杀：Redis 原子 + MQ/异步落库 [[秒杀设计]]

## 4. Seata（了解）

AT 模式基于 undo log；与 Dubbo/Spring Cloud 集成。raw 有死锁踩坑笔记——高并发下需谨慎。
