# 秒杀设计

[[订单服务]] 的秒杀子系统，面向高并发演示与百万 QPS 压测。

## 热路径（Redis + Lua 原子扣减）

```
POST /seckill/order
  → SeckillService.placeOrder()
      → Redis Lua 脚本（原子完成）:
          1. 检查 stock:{activityId} 是否存在
          2. user:{activityId} SET 去重（一人一单）
          3. DECR 扣库存，<0 回滚 → SOLD_OUT
          4. SADD 记录用户
          5. LPUSH queue:{activityId} 订单JSON
          6. HINCRBY metrics success
      → 返回 OK / DUPLICATE / SOLD_OUT
```

响应语义：200 成功 / 409 售罄 / 429 重复抢购。

## 异步落库

```
SeckillOrderConsumer（@Scheduled，默认每 50ms）
  → RPOP queue:{activityId} 批量（默认 500 条）
  → 批量 insert seckill_order（MySQL）
  → metrics persisted 计数
```

> ⚠️ 注意：异步是 **Redis List 队列 + Spring @Scheduled 轮询**，**不是 RocketMQ/Kafka**。代码注释写明生产应换 MQ；压测模式硬编码只 drain `activityId=1`。

## Redis Key（前缀 `seckill:`）

| Key | 含义 |
|-----|------|
| `stock:{id}` | 剩余库存 |
| `user:{id}` | 已购用户 SET |
| `queue:{id}` | 订单队列 LIST |
| `meta:{id}` | 活动元数据 HASH |
| `metrics` | 全局计数 HASH |

## 表

`seckill_activity`、`seckill_order`（`docs/sql/02_seckill_schema.sql`）。

## 未生产化项

- 无活动时间窗口校验（字段在未用）；无支付/取消/库存回滚。
- `seckill_activity.sold` 消费端未回写。
- 落库失败仅 log，无重试/死信。
- 无 Sentinel 限流（建议加 `@SentinelResource`）。

## 接口与压测

接口清单见 [[订单服务]]；压测脚本（k6/Gatling/wrk）在 `load-test/`，覆盖 smoke→ramp→million 与登录+秒杀混合场景。
