# 异步编程（面试题）

> 原理 [[spring/spring-async与线程池]] [[java/completablefuture-异步编排]] [[security/threadlocal-与上下文传递]]；并发系列 [[java/java-并发面试题]]。

## Q1. @Async 原理？为什么同类调用不生效？

Spring AOP 代理：调用走代理 bean 才切到 `AsyncExecutionInterceptor`。`this.xxx()` 无代理 → 同步执行。解决：注入 self、`ApplicationContext.getBean`、AspectJ 织入。

## Q2. @Async 和 MQ 怎么选？

| | @Async | MQ |
|---|--------|-----|
| 可靠性 | 进程内，宕机丢 | 持久化、重试 |
| 解耦 | 同应用 | 跨服务 |
| 秒杀 | 不用 | Redis Stream / RocketMQ |

## Q3. CompletableFuture 默认线程池？

无 Executor 参数时用 `ForkJoinPool.commonPool()`，CPU 核数-1，**不适合阻塞 IO**。

## Q4. thenApply 和 thenApplyAsync 区别？

前者在**完成线程**（或前一个 stage 线程）执行；后者提交到指定/默认 Executor。

## Q5. ThreadLocal 内存泄漏？

Entry key 弱引用，value 强引用；线程池线程长期存活且未 `remove()` → value 无法回收。必须 finally remove。

## Q6. 异步场景如何传递 traceId？

MDC 拷贝、TTL [[java/transmittable-thread-local跨线程]]、或 Header 显式传 [[java/mdc-日志链路上下文]]。

## Q7. Future.get 和 CompletableFuture 编排？

`get` 阻塞；CF 链式 + 超时 API 减少阻塞，见 [[java/completablefuture-异步编排]]。

## Q8. Spring @Cacheable 和 @Async 能同方法吗？

可以但顺序：外层取决于代理顺序（一般 Cache 在外）。自调用两者均失效。
